SyndicatFX

Full Guide

System Syndicate

Before you begin

  • A core is the package that holds an emulator. This page uses the SyndicatFX core, which runs Syndicate. You get it from the Releases page of the chimera-core-syndicatfx repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A frame is one picture the game draws. A game draws many of them each second.

Page 1 Choose the core

The first page asks you to pick a core, either an emulator or a game. Everything on the later pages depends on this choice.

OptionWhat it does
KindEmulator or Game. It decides which cores the Core list shows. SyndicatFX is a game core, which runs one game. The wizard opens on the kind you used last, when you have cores of that kind installed.
CoreLists the installed cores of that kind. Each line shows the core name, its version date and the systems it runs. Choose the SyndicatFX line. If you have two builds of one core installed, the line also shows the first eight characters of the package's fingerprint in square brackets.
SystemNames the machine to emulate. SyndicatFX has one, Syndicate, so the box is greyed out.
RendererChooses how the picture is drawn, for cores that offer a choice. SyndicatFX draws one way, so the box is greyed out and shows Software (Native).

A link at the bottom takes you to the Chimera issue page, for reporting problems and asking for features. If no core is installed, Next shows a message asking you to pick one.

Page 2 Set up the game

This page asks for the emulation settings. Every setting here shapes the emulated game, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

Settings

The grid lists the settings alphabetically. Click a row to read its description in the pane under the grid. A value that differs from the default is shown in bold. Right-click a row and choose Reset to put the default back. True or False settings and settings with a fixed set of choices are picked from a list. Number and text settings are typed in. The System and Renderer are not in the grid because Page 1 already asked for them. SyndicatFX has 2 settings in the grid. All of them are always shown.

SettingAllowed valuesDefaultWhat it does
LanguageEnglish, French, ItalianEnglishThe game's language (the original '-c' option). The menus come from SyndicatFX's translations, and the mission briefings from the CD's own sets. It changes the game (its texts and layout), so a movie records it.
SoundSound Blaster, NoneSound BlasterThe sound card chosen in the game's setup. 'Sound Blaster' is the default and the only card the game supports. Its digitized sounds play one at a time, as on the card, and the music plays on its FM chip through the game's own driver. 'None' is no card (the original '-s' option). The game waits for its song to end before a won or lost mission ends, so the choice changes the game, and a movie records it.

Page 3 Provide firmware

This page asks where to find the firmware and game data files the core needs. SyndicatFX always asks for at least one, so this page always appears. The list changes when you go back and change a setting.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Create stays greyed out until every row that is not optional has a file.

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard shows the reason. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

Some cores add a page that compiles the game's code before the project is made. SyndicatFX does not, so you will not see it.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
