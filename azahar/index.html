Azahar

Quickstart

System Nintendo 3DS

Quickstart

  1. Put the Azahar core file (it ends in .chimeraCore) in the Cores folder next to Chimera.exe.
  2. Open the File menu and choose New Chimera Project.
  3. Page 1. Choose Azahar in the Core list, then press Next.
  4. Page 2. Press Add under Game and pick your game files. Press Next.
  5. Page 3. Change settings if you want to. The defaults work for most games. Press Next, or Create if that is what the button says.
  6. Page 4 only appears when your choices need firmware files. Give each file in the list, then press Create.
  7. Chimera opens the new project in TAStudio (its input editor) at the first frame.

You can also drag a game file onto the Chimera window. The wizard then opens with the core and the file already chosen.

Before you begin

  • A core is the package that holds an emulator. This page uses the Azahar core, which runs Nintendo 3DS. You get it from the Releases page of the chimera-core-azahar repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A savestate is a copy of the whole machine at one moment. You can return to it later.
  • A recompiler (also called a JIT) translates the console's code into your computer's code before running it, which is fast. An interpreter reads the console's code one step at a time, which is slower.
  • A frame is one picture the game draws. A game draws many of them each second.

Buttons on every page

ButtonWhat it does
BackReturns to the page before. It is greyed out on Page 1. Pages that do not apply are skipped. Your answers are kept.
NextGoes to the next page. On the last page it is called Create. If something is missing, a red message at the bottom left says what.
CancelCloses the wizard and creates nothing.

Page 1 Choose the core

The first page asks you to pick a core, either an emulator or a game. Everything on the later pages depends on this choice.

OptionWhat it does
KindEmulator or Game. It decides which cores the Core list shows. Azahar is an emulator. The wizard opens on the kind you used last, when you have cores of that kind installed.
CoreLists the installed cores of that kind. Each line shows the core name, its version date and the systems it runs. Choose the Azahar line. If you have two builds of one core installed, the line also shows the first eight characters of the package's fingerprint in square brackets.
SystemNames the machine to emulate. Azahar has one, Nintendo 3DS, so the box is greyed out.
RendererChooses how the picture is drawn. The choices are Software (Native), Hardware (OpenGL). The default is Software (Native). A Hardware choice uses your graphics card. It is fast, but the picture is drawn outside the savestate, so video can differ on another computer. A warning appears under the box when you pick one.

A link at the bottom takes you to the Chimera issue page, for reporting problems and asking for features. If no core is installed, Next shows a message asking you to pick one.

Page 2 Add your files

This page asks for the game files and other data. The core decides what appears here. Azahar shows 2 groups of files. Hover over a group to see the core's own help text.

GroupHow manyFile typesWhat it is for
GameExactly one.3ds, .cci, .cxi, .app, .3dsx, .elfA DECRYPTED dump. It can be a cartridge (.3ds or .cci), an executable (.cxi or .app) or homebrew (.3dsx or .elf). Azahar does not decrypt. An encrypted dump is refused with a message that says so. An old dump that was decrypted but whose header still says 'encrypted' is recognised and runs.
Save dataAt most one.zipWhat the game already saved, as Emulator > Export Save Data... wrote it. It is a .zip of the SD card's 'Nintendo 3DS' folder (the game's save data and extra data). It is put back onto the machine's SD card before the game starts.

Controls in each group

  • Add opens a file picker titled Add to and the group name. It starts in the ROM folder set under Config, Paths. It filters to the group's file types, and you can switch it to All files. You can select several files at once.
  • Remove takes the selected row out of the list. It does not delete the file on disk.
  • Drag and drop works on each list. A file you drop lands in the group you drop it on. Folders are ignored.

Rules

  • Groups whose How many is Exactly one or At least one need a file. These are Game. Next will not continue until each has a file.
  • Each group's title shows how many files it takes and the file types it expects. A file with another extension is still added, and a message at the bottom tells you it is not what the group expects.
  • Adding a file with the same name as one already in the group does nothing.

Starting from a dropped file

If you drag a file onto the main Chimera window, the wizard opens with the core that claims the file's extension already chosen. The file goes into the first group that lists that extension. Azahar claims .3ds, .3dsx, .app, .cci, .cxi, .elf.

Page 3 Set up the machine

This page asks for the emulation settings. Every setting here shapes the emulated machine, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

Settings

The grid lists the settings alphabetically. Click a row to read its description in the pane under the grid. A value that differs from the default is shown in bold. Right-click a row and choose Reset to put the default back. True or False settings and settings with a fixed set of choices are picked from a list. Number and text settings are typed in. The System and Renderer are not in the grid because Page 1 already asked for them. Azahar has 15 settings in the grid. All of them are always shown.

SettingAllowed valuesDefaultWhat it does
AES KeysTrue or FalseFalseWhether the project includes the console's AES keys (aes_keys.txt, dumped from your own console). A decrypted game needs none, and this package includes none. They are needed to install and run .cia content, for amiibo and for some online-account features.
Clock at Power-On946684800 to 2145916800946684800What the console's clock shows when the machine starts, in seconds since 1970-01-01 (UTC). The default is 2000-01-01 00.00.00, the earliest date a 3DS can be set to. After the start the clock runs with the emulated console and never with your computer. A game that takes its random numbers or its calendar from the clock plays differently with another value, so it is part of the machine.
CPUjit, interpreterjitHow the console's ARM11 processor is emulated - with dynarmic's recompiler, which is fast, or with Azahar's interpreter. Both are meant to give the same result. The interpreter is there to find out whether a problem comes from the recompiler or from the game.
CPU Clock (%)5 to 400100The speed of the ARM11 processor as a percentage of the real console's (Azahar's CPU clock setting). Above 100, a game that slows down in busy scenes slows down less. It changes how the game runs, so a movie needs the same value.
Internal Resolution1x, 2x, 3x, 4x1xHow many times the console's own resolution the OpenGL renderer draws at (Azahar's Internal Resolution). At 2x the stacked picture is 800x960. The software renderer always draws at 1x. This is part of the machine and not only of the picture. What the graphics card draws is written back into the console's memory reduced to the console's size, and those bytes differ from the ones a 1x frame leaves. A movie therefore needs the resolution it was made with. Above 1x every savestate also holds the renderer's pictures at full size, so states are larger and saving one takes longer.
Large Screen Proportion1 to 164With the 'large' layout, how many times larger the large screen is than the small one. Azahar's default is 4.
Linear FilteringTrue or FalseTrueWhether the OpenGL renderer smooths a screen when it scales it into the picture (Azahar's Enable Linear Filtering). The difference shows where a screen is not at a whole multiple of its own size, such as the small screen of the 'large' layout. It changes the picture only.
Modelnew3ds, old3dsnew3dsWhich console this is - a New Nintendo 3DS (256 MB of memory, a faster processor mode, the ZL and ZR buttons and the C-Stick) or the original Nintendo 3DS. Azahar's default is the New 3DS, which runs every game. A game made for the original model may be timed differently on the new one. It is part of the machine, so a movie needs the same model.
Motion ControlsTrue or FalseFalseWhether the motion sensors (accelerometer and gyroscope) take input through the six Accel and Gyro axes. With this off the console lies still and flat, and those axes are removed from the input columns.
Regionauto, jpn, usa, eur, aus, chn, kor, twnautoThe console's region. 'auto' uses the game's own region. A game can read it, so it is part of the machine.
Screen Layoutstacked, single, large, side-by-sidestackedHow the two screens are placed in one picture (Azahar's Screen Layout). 'stacked' puts the top screen above the bottom one (400x480). 'single' shows the top screen alone (400x240). 'large' shows one screen at full size with the other one small next to it, and Large Screen Proportion says how small. 'side-by-side' shows both at full size (720x240). Swap Screens exchanges the two screens in any layout. The layout changes the picture only, with one thing to know. The Touch axes are a position in the picture, so a touch lands where the layout puts the bottom screen. A movie that uses touch needs the layout it was made with, and with the top screen alone nothing can be touched.
Seed DatabaseTrue or FalseFalseWhether the project includes seeddb.bin, the per-game seeds that some eShop games are encrypted with. It is only used together with AES Keys.
Swap ScreensTrue or FalseFalseExchanges the two screens in the layout. With 'single', the bottom screen is shown alone (320x240). With 'large', the bottom screen is the large one.
Upright ScreensTrue or FalseFalseShows the console turned on its side, for games that are held like a book. The picture is turned a quarter turn, and its width and height change places.
User Nameany text(empty)The user name in the console's own settings, one to ten characters. Games read it, for example as the owner of a save file or in a greeting. It is part of the machine, so a movie made with one name needs that name. Left empty, it is Azahar's default, AZAHAR.

Page 4 Provide firmware

This page asks where to find the firmware files your choices need. It only appears when at least one setting calls for a file. With some settings it is skipped, and the page before it ends with Create instead of Next. The list changes when you go back and change a setting.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Create stays greyed out until every row that is not optional has a file.

Which files can be asked for

Azahar can ask for up to 2 files. Only the rows your choices call for appear. A description that starts with an italic condition is only asked for in that case.

FirmwareExpected fileSHA1What it is

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard goes back to Page 2 and says why. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

Some cores add a page that compiles the game's code before the project is made. Azahar does not, so you will not see it.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
