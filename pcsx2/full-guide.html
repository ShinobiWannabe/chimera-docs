PCSX2

Full Guide

Systems PlayStation 2 · NAMCO System 246 · NAMCO System 256 · NAMCO Super System 256

Before you begin

  • A core is the package that holds an emulator. This page uses the PCSX2 core, which runs PlayStation 2, NAMCO System 246, NAMCO System 256, NAMCO Super System 256. You get it from the Releases page of the chimera-core-pcsx2 repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A savestate is a copy of the whole machine at one moment. You can return to it later.
  • A lag frame is a frame in which the game did not read your input. The lag count is how many there have been.
  • A hash is a fingerprint of a file's contents, like a SHA1.
  • A recompiler (also called a JIT) translates the console's code into your computer's code before running it, which is fast. An interpreter reads the console's code one step at a time, which is slower.
  • DIP switches are small switches on a circuit board that set options for the machine.
  • A frame is one picture the game draws. A game draws many of them each second.

Page 2 Add your files

This page asks for the game files and other data. The core decides what appears here. PCSX2 shows 5 groups of files. Hover over a group to see the core's own help text. The file types offered in each group narrow to the System you chose on Page 1.

GroupHow manyFile typesWhat it is for
Disc or programExactly one.iso, .bin, .img, .chd, .cso, .zso, .gz, .elfShown when System is PlayStation 2.
What the machine runs. This is usually a DVD or CD image. It can be a plain .iso or .bin (with sectors of 2048 or 2352 bytes, with or without a .cue file beside it) or a compressed image (.chd, .cso, .zso, .gz). It can also be a PS2 EXECUTABLE (.elf), which is how homebrew and test programs are distributed. The tray then stays empty and the machine is given the program to run, exactly as it would run a disc's own boot file. The first four bytes of the file decide which it is, not its name, so an executable with any name still starts. A project with no file at all is a console showing its own browser, and that machine can be started too. But the New Project window asks for a file, because a movie is usually of a game.
Security dongleExactly one.ps2, .bin, .mcd, .mc2Shown when System is one of NAMCO System 246, NAMCO System 256, NAMCO Super System 256.
The game's security dongle. Without it an arcade game does not start at all. It is not a chip. It is a copy of the game's own COH-H10020 MEMORY CARD, 8,650,752 bytes long (8 MB plus error-correction data, the size PCSX2 keeps a card at), and it holds the boot software the board runs. Each game has its own, and another game's dongle starts nothing. The file is usually named after NAMCO's part number or after the label on the cartridge, with whatever extension the person who copied it chose. The name does not matter. The file is taken as it is and put in the board's card slot 1, where the cabinet has it. The file is never changed. The project and the movie record exactly which file it was. The boot software rewrites the dongle as it runs, and what a run wrote is exported as save data and is not written back into your copy.
Game mediaExactly one.chd, .iso, .bin, .img, .cueShown when System is one of NAMCO System 246, NAMCO System 256, NAMCO Super System 256.
The game's own medium - the CD, DVD or hard disk that holds its data. It is read by the NAMCO board's disk controller (ATA/ATAPI) and not by the console's drive, because a COH-H board has no disc drive. The Media setting says which of the three it is, because the file itself does not. These are usually kept compressed as .chd. A plain .iso or .bin works too. This core works out how the sectors are laid out in the file (2048-byte data sectors, raw CD frames of 2352 or 2448 bytes, 2336-byte Mode 2, or raw DVD sectors of 2064 bytes) and does not rely on the extension. An incomplete file is refused with a message that says so, because a game that reads past the end of one fails much later and much less clearly.
Boot programExactly one.elf, .binShown when System is one of NAMCO System 246, NAMCO System 256, NAMCO Super System 256.
The program the board starts. On a real cabinet this is Sony's PSALM boot.bin, which is on the board. You do not have to copy it from a board. Proverb (github.com/PS2Homebrew-arcade/proverb, AFL-3.0) is an open alternative that starts the same games, and it comes with one boot.elf for each NAMCO part number. For example bin/NM00004/boot.elf is the one for Tekken 4. Either one works here. The one a project uses is part of the machine, so two projects with different boot programs are different machines and cannot share movies.
Save data0 to 3.ps2, .nvm, .binWhat the machine starts with already saved. On a PlayStation 2 that is the memory cards and the console's own settings memory (NVRAM) - memcard1.ps2, memcard2.ps2 and bios.nvm. On a NAMCO board it is sram.bin, the 32 KB of battery-backed settings memory on the board, which holds the coin settings and the options of the game's own test menu. These are the files that Emulator > Export Save Data... writes, given back under the same names. A run can then continue where another stopped, or start from a cabinet that somebody set up in the test menu. The files are never changed. The project and the movie record exactly which files they were, so a movie that starts from a saved game can be played back by anyone who has the same files. A file whose name nothing reads is refused when the project loads, and the message names it, so it is never silently ignored. Leave it empty and the machine starts with blank cards and a board that nobody has set up, which is a new console and a new cabinet.

Controls in each group

  • Add opens a file picker titled Add to and the group name. It starts in the ROM folder set under Config, Paths. It filters to the group's file types, and you can switch it to All files. You can select several files at once.
  • Remove takes the selected row out of the list. It does not delete the file on disk.
  • Up and Down arrows appear in the groups that take more than one file, which are Save data. They move the selected row. The order is kept in the project.
  • Drag and drop works on each list. A file you drop lands in the group you drop it on. Folders are ignored.

Rules

  • Groups whose How many is Exactly one or At least one need a file. These are Disc or program, Security dongle, Game media, Boot program. Next will not continue until each has a file.
  • Each group's title shows how many files it takes and the file types it expects. A file with another extension is still added, and a message at the bottom tells you it is not what the group expects.
  • Adding a file with the same name as one already in the group does nothing.
  • A .cue file (a small text file that lists a disc's track files) counts as one row and shows how many track files it brings. All its track files must sit in the same folder as the .cue file, or the wizard refuses it and names the missing file.
  • A group is greyed out when its condition is not met. The description of the group starts with that condition in italics.

Starting from a dropped file

If you drag a file onto the main Chimera window, the wizard opens with the core that claims the file's extension already chosen. The file goes into the first group that lists that extension. PCSX2 claims .bin, .chd, .cso, .elf, .gz, .img, .iso, .zso.

This page asks for the emulation settings. Every setting here shapes the emulated machine, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

CPU Coresrecompiler, interpreterrecompilerWhich processor implementations run the machine. The recompilers translate the code of the EE, the IOP and both VUs to x86 code as it runs. This is how PCSX2 itself normally plays, and it is several times faster. The interpreters execute every instruction one at a time, which is the slowest and most literal way. They are DIFFERENT MACHINES, because the recompiler's EE floating point does not give the same results as the interpreter's. So the project and the movie record the choice, and a movie made with one does not play back with the other.
Deinterlacingauto, adaptive, adaptive-bff, weave, weave-bff, blend, bob, offautoHow the console's two fields become one picture, when the game produces fields at all. In an interlaced mode a PS2 sends out HALF a picture per frame - 224 lines of 448, with the other half in the next frame. Something has to decide what a single field looks like as a whole frame. But many games draw WHOLE frames instead, and running one of those through a deinterlacer destroys half of it - the picture then always has one row from this frame and one row from the previous frame. 'auto' asks the machine which of the two it is doing. It leaves a whole frame alone and rebuilds a field picture with 'adaptive'. This is what PCSX2 itself does, and it should normally be left on. The other choices force one method. 'adaptive' compares this field with the three before it and decides for each pixel whether to keep a line or to make one from the lines above and below. Still pictures keep their full detail, and moving ones show no comb pattern. 'weave' puts each field's lines back in their proper places. That is the full picture the television showed, and fast motion shows a comb pattern, as it does on the real machine. 'weave-bff' and 'adaptive-bff' are the same with the order of the fields swapped, for a game that looks one line out of place. 'blend' is weave with the comb pattern softened. 'bob' shows the current field alone, scaled up. It never shows a comb pattern, and it has half the vertical detail. 'off' hands over the field stretched and places nothing, which makes a still screen move up two lines and back down on every frame.

Page 4 Provide firmware

This page asks where to find the firmware files your choices need. It only appears when at least one setting calls for a file. With some settings it is skipped, and the page before it ends with Create instead of Next. The list changes when you go back and change a setting or the System.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Create stays greyed out until every row that is not optional has a file.

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard goes back to Page 2 and says why. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

Some cores add a page that compiles the game's code before the project is made. PCSX2 does not, so you will not see it.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
