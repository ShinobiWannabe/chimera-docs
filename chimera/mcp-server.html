Chimera

MCP Server

What an MCP server is

An AI agent is a program that uses an AI model to carry out a task for you. Claude Code, Claude Desktop and Cursor are agent programs. MCP stands for Model Context Protocol. It is an open standard that lets an agent program use another program. A program that follows it is an MCP server.

An MCP server publishes a list of tools. Each tool has a name, a short description and named inputs. The agent program reads the list. When the model wants something done, it picks a tool and fills in the inputs. The server runs the tool and sends back an answer. An answer can be text or a picture.

Chimera has an MCP server. It lets an agent look at the project you have open. It can read the movie input, the picture on the screen, the memory and the processor registers. It can search memory for a value. If you allow it, it can also edit the input, move the playback position, save branches, add markers and write to memory. Everything it does shows in TAStudio as it happens.

The server runs only on your computer. Chimera has no network code, and the server uses none. It is off until you start it, and you can stop it at any time.

What it is used for

  • Finding a memory address. The agent runs a search, plays the game forward, and narrows the list until a few addresses are left.
  • Finding the frame where something happens, such as the first frame a counter reaches a number.
  • Reviewing a movie. The agent reads the input and looks at screenshots, then tells you what it sees.
  • Trying an edit. The agent changes the input, plays it, looks at the result, and undoes it if it does not work.
  • Doing the same job on many frames. A slow job done by hand, such as clearing a button over a long stretch, takes one call.
  • Working with no window. The agent opens a game on a machine of its own, plays a movie and saves the result as a project.

How the agent reaches Chimera

An agent program talks to an MCP server by starting it as a second program and trading lines of text with it, over the text channels every program has, called standard input and output. A running Chimera window cannot be started by the agent, so a small program sits in between.

  1. The agent program starts chimera-mcp and talks to it over standard input and output.
  2. chimera-mcp passes each request over a local pipe to the Chimera window, and passes each answer back. A local pipe is a channel between two programs on one computer. On Windows it is a named pipe. On Linux it is a pair of FIFO files, which are special files that act as a channel, in your runtime folder. Only your own user can open it.
  3. The Chimera window runs the request on the machine the core runs and sends the answer.

No socket is opened, no port is listened on and no name is looked up. MCP can also run over HTTP, and Chimera does not offer that.

When the server is stopped, or Chimera is not running, chimera-mcp still lists the tools. Every call then answers with a sentence that says how to start the server. So the agent program does not need to be restarted when you start or restart Chimera.

If you run two Chimera windows as the same user, give each its own name. Set the environment variable CHIMERA_MCP_NAME to the same word for one Chimera and for the chimera-mcp that belongs to it.

How to set it up

You do this once for each agent program.

  1. In Chimera, open the Tools menu and choose MCP Server...
  2. Find the box under the line that begins with To set up an agent. It holds the command. Press Copy to put it on the clipboard.
  3. Run the command in a terminal. For Claude Code the command looks like this, with your own path in place of the one shown.

claude mcp add chimera -- "/path/to/chimera/dll/chimera-mcp"

The window fills in the real path of the file on your computer. For another agent program, add a local server that runs that same file, with no arguments. Restart the agent program if it asks you to.

How to use it

  1. Open or create a project in Chimera. TAStudio opens with it.
  2. Open the Tools menu, choose MCP Server... and press Start. The window says the server is started and that no agent is connected. The title bar of the Chimera window begins with MCP server started, and the icon of the menu item carries a green dot. Both stay until you stop the server, so it cannot be left on without you noticing.
  3. Start your agent program and ask it to do something with Chimera. Its first call is usually status. When it connects, the window shows the name and version of the agent program.
  4. To let the agent make changes, tick Allow the agent to make changes. Leave it unticked when you only want it to look.
  5. Watch the log in the window. Each call is one line. Press Save Log... if you want a copy as a text file.
  6. When you are done, press Stop. Stopping ends any call that is running with an error to the agent. Closing the window does not stop the server. Closing Chimera does.

You can ask for things in plain words. For example, ask the agent to find the address that holds the number of lives, or to find the frame where the boss health first reaches zero, or to look at the first 600 frames and describe where time is lost.

For runs where nobody clicks, Chimera accepts two launch options. --mcp-server starts the server at launch, as pressing Start does. --mcp-allow-changes next to it ticks the box. Nothing else starts the server or allows changes, and no setting in a config file can.

The MCP Server window

It stays open beside the Chimera window and updates a few times a second.

What protects your work

  • Looking is the default. With the tick box off, every tool that changes the movie or the machine is refused. The refusal says which tick box allows it.
  • Your work is kept first. Before the agent's first change after the server starts, Chimera saves a branch of the movie as it is, with a note that says it was made before the agent's changes and gives the date and time. If the branch cannot be saved, nothing is changed. Every change is then refused until you stop and start the server again. The engine holds this rule, so no path through the window skips it.
  • Every edit is an ordinary TAStudio edit. It shows in the Piano Roll and is a step in the undo history, named for what the agent did, such as Agent, set input, frames 10 to 20. You can undo it as you undo your own edits.
  • The agent cannot save, open or close projects in the window, and it has no access to your files there. Saving stays your act.
  • Memory writes are reported. A movie cannot reproduce a write to memory. From the first write on, the status tool says that memory was written and gives the frame, and the log shows it. This lasts until the server is stopped.
  • Calls run between frames. A call runs in the part of Chimera that runs the machine, after one frame and before the next, and never beside it. If a dialog is open in Chimera, the call waits. After 30 seconds the agent is told Chimera is busy and the call is not run. A call that waited more than 25 seconds is dropped, so a call the agent was told had failed is never run later. The log marks it as not run.
  • One agent at a time. The server serves one agent program, and one Chimera window.

What it can do

With Chimera

The status tool is the agent's first look. It gives the project name, the project file, whether the project has unsaved changes and whether playback is paused. It also gives the core and the system, the frame the machine is on, the length of the movie, the size of the picture, the frame rate, whether the core has stopped, whether changes are allowed and whether memory was written.

  • It can take a picture of the current frame as a PNG, scaled down to the width it asks for.
  • It can read memory and registers at the frame the machine is on, and write them when changes are allowed.
  • It can read the movie input as text, and change it when changes are allowed.
  • It can start a RAM search of its own, which is separate from the RAM Search window.
  • It cannot open, save or close projects in the window, load a core, change settings, press hotkeys, run Lua scripts, record sound or encode video. It cannot be used by more than one agent at once or from another computer.

With cores

No tool names a system, a control or a core. Every name comes from the core that is open, so the same tools work with every core on this site.

  • Controls. The controls tool lists the buttons and axes of the machine by name, in the order of the columns of a movie line, with the rest value of each axis. A control the machine does not have plugged in is marked as not active.
  • Memory. list_memory lists the core's domains and buses. A domain is a block of memory addressed from 0. A bus is an address space as the processor sees it. Each shows its size and whether it can be written. A RAM search runs over a domain only, and only over a domain for which the core gives its own memory.
  • Registers. registers shows the processor registers for a core that gives them. set_register works only for a core that lets registers be written.
  • Properties. A game core has named values, such as a player's position or a score. list_properties and get_property read them as a person reads them, and an array element is asked for as Name[3]. Emulator cores have none. set_property sets one from text, which can be a number, a name the value can take, or true or false.
  • A core that stopped. If the core has crashed or stopped, status says so and gives the reason.

With TAStudio

The agent works through TAStudio, so what it does appears in the window as it happens and can be undone.

Part of TAStudioWhat the agent can do with it
Piano Roll and inputRead the input of any range of frames. Replace lines of input, set or clear buttons and axes over a range, insert empty frames and delete frames. The edits show in the Piano Roll at once.
PlaybackMove the playback position to a frame, or play forward until a memory value or property meets a condition. You see the game move. See Playback.
GreenzoneGoing back uses the saved states, and going forward plays the movie's input. Changing input before the current frame drops the saved states after it, exactly as an edit by hand does. See Greenzone.
BranchesList the branches, save one with a note and load one by its number. Numbers start at 1, as in the Branches box. See Branches.
MarkersList the markers and add one with a text. The three markers every movie has of its own are shown as not placed by a person. See Markers.
Undo historyUndo the last step, whoever made it. This is the same as Edit, then Undo in TAStudio.

It cannot record new input by playing, use Lua, or change TAStudio settings. advance_until plays only the input the movie already has and never past its end, so it adds no frames.

The tools

The list is the same for every agent program. Each tool states whether it only reads. A program that follows MCP can use that to ask you less often. The limits below are the ones the server enforces. A call that goes past a limit is refused with a sentence that says what is allowed.

Tools that look

ToolWhat it does
statusThe state of Chimera and the machine, as described above.
controlsThe buttons and axes by name, the rest value of each axis, and the key that names the columns of a movie line.
get_inputThe movie input for a range of frames, one line a frame, as the movie file holds it. In a line, groups are separated by a vertical bar, a dot is a button not pressed, a letter is a button pressed and an axis is a number. Limits. From frame 0 or more. Up to 1000 frames a call, 100 when left out.
screenshotThe picture of the current frame as a PNG, with the frame number and the picture size. A large picture is shrunk by a whole-number step so that it is no wider than the width asked for. Limits. Width 32 to 4096, 800 when left out.
list_memoryThe domains and buses, each with its size and whether it can be written.
read_memoryValues at an address in a domain or bus, as 8, 16 or 32 bit numbers, signed or not, in little or big byte order. It also returns the raw bytes in hex. Limits. Up to 4096 bytes a call.
registersThe processor registers with their sizes and values, and the executed cycles when the core counts them. Limits. Only for a core that gives registers.
list_propertiesA game core's named values with type, size and current value. It can filter by part of a name. Limits. Up to 500 a call, 100 when left out. It also says how many matched.
get_propertyOne named value as a person reads it.
list_branchesEach branch with its number, frame, time taken, note and whether it is the current one.
list_markersEach marker with its frame and text and whether a person placed it.

Tools that search memory

These run a RAM search that belongs to the agent. It is separate from the RAM Search window. They only read, so they need no permission. There is one search at a time. Starting a new one drops the old one. A search also ends when the project is closed or the server is stopped.

ToolWhat it does
search_startStarts a search over a domain. Every address becomes a candidate and its value now is remembered as its previous value. Limits. A domain, not a bus. A value size of 1, 2 or 4 bytes. Byte order can be chosen.
search_filterKeeps the candidates whose value now is equal to, not equal to, greater than, at least, less than or at most a number you give, or the previous value when you give none. Then it remembers the value now. It answers how many are left. Limits. Can compare as signed numbers.
search_resultsThe candidates left, lowest address first, with the value now and the previous value. Limits. Up to 500 a call, 50 when left out.
search_undoTakes the last filter back. Limits. Fails when there is no filter to take back.

The usual way to use them is to start a search, make the game change the thing you are looking for, filter for different or greater or less, and repeat until few addresses are left. The agent makes the game change by moving the playback position, or you play while it waits.

Watching values

watch names up to 32 values to follow. A value is a place in memory, given by domain, address and type, or a game core's property. From then on the answers of status, seek, advance_until and load_branch carry a list called watches with the value of each. This saves one read call after every move. The list you give replaces the one before it. An empty list ends watching. The watch lasts until the server is stopped.

Tools that change things

Every tool here is refused until the tick box is ticked. Before the first of them, a branch of your movie is saved.

ToolWhat it does
seekMoves the playback position to a frame, back or forward. It answers when the machine is there. If something interrupts it, it says the position stopped on another frame. Limits. A frame from 0 to the movie length.
advance_untilPlays the movie forward from the current frame until a memory value or property meets a condition, then stops on that frame. The conditions are equal, not equal, greater, at least, less, at most, and changed, which means different from the value at the start. It says whether the condition was met, how many frames it played and what stopped it, which is the condition, the end of the movie, the frame limit or an interruption. Limits. Up to 100000 frames, 600 when left out. It cannot start at the end of the movie.
set_inputReplaces the input from a frame on, one line a frame in the form get_input gives. Lines past the end of the movie are added. Every line is checked first and none is written if one is wrong. It is one step in the undo history. Limits. Up to 1000 lines a call.
set_buttonsPresses or releases buttons and sets axes by name over a range of frames. Controls it does not name keep what they had. It is one step in the undo history. Limits. Up to 10000 frames a call, 1 when left out. It must name at least one control.
insert_framesInserts empty frames before a frame. The input from there on moves later. Limits. Up to 100000 a call.
delete_framesDeletes frames from a frame on. The input after them moves earlier. It stops at the end of the movie. Limits. Up to 100000 a call.
undoUndoes the last step in the undo history, whoever made it. Limits. Fails when there is nothing to undo.
save_branchSaves a branch, which is the input and the machine as they are now, with an optional note. It answers with the branch number.
load_branchLoads a branch by its number. The input and the machine become what the branch saved. Limits. A number from 1 to the count of branches.
add_markerPlaces a marker with a text on a frame.
write_memoryWrites values to a domain or bus at the current frame. A movie cannot reproduce it, so it is for testing a guess. Limits. Up to 4096 bytes a call. The domain or bus must be writable.
set_propertySets one named value of a game core from text. A movie cannot reproduce it. Limits. Game cores only.
set_registerSets a processor register. A movie cannot reproduce it. Limits. Only for a core that allows it.

write_memory, set_property and set_register change the machine, not the movie. They are not steps of the undo history. If you want to remove their effect, load a branch or seek to an earlier frame.

Examples of what to ask

Find where the game keeps a value

  1. Ask the agent to find the address that holds the player's lives.
  2. It calls list_memory and starts a search on the main RAM domain.
  3. It moves the playback position to a frame where you lose a life, then filters for a value that is less than before.
  4. It moves again and filters for a value that is equal to the number it sees on the screen. It repeats until a few addresses are left, then reads them with read_memory and reports the likely one.

Find the frame where something happens

  1. Ask the agent to find the first frame where the boss health reaches zero.
  2. It names the address with watch, so each answer carries the value.
  3. It calls advance_until with the condition equal to 0. One call plays as far as needed and stops on the frame. Without this tool it would need one call for every frame.

Try an edit and check it

  1. Tick Allow the agent to make changes. Ask the agent to hold Right for frames 300 to 340 and tell you if the character moves farther.
  2. Chimera saves a branch first. The agent calls set_buttons, then seek to frame 340 and screenshot, and compares with what it saw before.
  3. If it is not better, the agent calls undo. You can do the same yourself in TAStudio at any time.

Review a movie

  1. Leave the tick box off. Ask the agent to look through the movie and list places where time may be lost.
  2. It reads the input with get_input in blocks of up to 1000 frames, looks at pictures with screenshot and notes the markers with list_markers.
  3. It tells you what it found. Nothing is changed.

Working without a window

An agent can also work with no Chimera window at all. When chimera-mcp is started with a cores folder, it reaches no window. It opens a machine of its own, inside its own program, and the agent has that machine to itself. Use it for batch jobs, for checking a movie, or for exploring a game while you are away.

claude mcp add chimera-headless -- "/path/to/chimera/dll/chimera-mcp" --cores "/path/to/chimera/Cores" --work "/path/to/work" --files "/path/to/games"

OptionWhat it does
--coresThe folder of core packages. Nothing else is read as a core. Required for this mode.
--workThe one folder that anything is written in. It may be read from too. Required.
--filesA folder games, projects, movies and firmware may be read from. You can repeat it.
--gpuAsks for the GPU bridge, for a core that draws on the graphics card.
--historyThe memory in MiB for the saved states that make going back cheap. 256 when left out.
--toolsPrints the tools one to a line, with their descriptions, and exits. It also marks the tools that change things and the tools that exist only without a window.

The agent then calls these tools, along with every tool above.

ToolWhat it does
list_coresThe packages in the cores folder, each with its file, its name, its version and the machines it is.
describe_coreWhat one core declares. That is its settings, the firmware it may ask for and the slots that hold files in a project.
open_gameStarts a project from a core and game files, with an empty movie. Files are given by slot, firmware by path and settings by key. A project open before is closed without being saved.
open_projectOpens a project file. Its files are looked for beside it and in the allowed folders, and must be the ones it records.
save_projectSaves the project with its input, branches and markers, inside the work folder. A project saved this way opens in the Chimera window like any other.
export_movieWrites the input alone to a file inside the work folder, as the command-line program chimera-run plays it.
closeCloses the machine. What was not saved is lost.

How it differs from the window

  • Nothing asks for permission. The machine is the agent's own, so tools that change things are never refused and no branch is saved first.
  • The engine holds the movie and its own undo history, which keeps the last 100 edits. There is no TAStudio, so there is no recording mode and no lag log.
  • A branch keeps the input and the frame but not the state of the machine. Loading one plays its input up to its frame.
  • Firmware is given by path, one file for each firmware id that describe_core lists. It does not look in Chimera's Firmware folder or its settings, because only the window knows those.
  • One machine at a time. Opening another closes the first without saving it.

Which files it may touch

An agent picks every path it passes. So the limits are set when chimera-mcp is started, and a call cannot change them.

  • Core packages are read only from the --cores folder.
  • Games, projects, movies and firmware are read only from the --files folders and the work folder.
  • Everything is written inside the work folder.
  • Any other path is refused. That includes one that climbs out of a folder with two dots, or goes through a link.
  • The files of a project are checked against the fingerprints, called hashes, that it records. A mismatch is an error, since there is no person to ask.
  • It downloads nothing. Games and firmware are your own files.

What it does not do

  • Sound, video encoding, running Lua scripts and CPU traces.
  • More than one agent at once, or one agent on several Chimera windows.
  • Any connection from another computer or over a network.

The agent program is a separate program from Chimera. Chimera sends nothing over a network, but it does give the agent program the answers of the tools, such as pictures, memory values and input. What that program does with them, including whether it sends them to an AI provider, depends on the program. Check its own settings before you open a project you want to keep private.
