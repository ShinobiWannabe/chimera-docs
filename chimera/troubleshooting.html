Chimera

Troubleshooting

Common problems and the messages Chimera shows, what each one means and how to fix it. Messages are quoted the way Chimera writes them. A word such as X stands for a name, a number or a file that Chimera fills in.

A few words used on this page. A core is a package that holds one emulator or one game, in a file that ends in .chimeraCore. Firmware means system files copied from real hardware, such as a BIOS. A SHA1, also called a hash, is a fingerprint of a file's contents. A movie is the recording of your inputs, and it desyncs when it plays back differently from how it was made.

Page 1, Page 2 and so on are the pages of the New Chimera Project wizard, which opens from the File menu when you create a project. See the Quickstart.

Where to Learn the Basics

How Do I Start My First Game?

Get a core, put it in the Cores folder, then choose File, New Chimera Project and follow the wizard pages. See the Quickstart. Each core also has its own Quickstart in the Cores section with the exact choices for that core.

Where Do I Get Cores?

Each official core has a project page on GitHub named chimera-core followed by the core name, in the ToolAssisted-run organization. Download its .chimeraCore file and put it in the Cores folder beside Chimera. See Before you begin and The Core list on Page 1 is empty.

How Do I Use TAStudio?

TAStudio is the window where you edit a movie one frame at a time. Start with the TAStudio Quickstart, then read Piano Roll, Playback, Markers and Branches.

How Do I Watch a Value in Memory?

RAM Watch keeps a list of memory values on screen while the game runs. See RAM Watch and its Zelda example.

How Do I Find Where a Game Keeps a Value?

RAM Search finds memory addresses by how their values change. The RAM Search example finds Link's rupee count one search at a time.

How Do I Write and Run a Lua Script?

Lua is the scripting language Chimera runs. Learn the language on Lua Basics, then the most used functions on Basic Examples. Every function is on Lua References. Run scripts from the Lua Console.

How Do I Record a Video, Set Keys or Let an AI Agent Help?

See Encoding for video, Controllers and Hotkeys for keys, and MCP Server for an AI agent. Menu Options describes every menu.

Cores

The Core List on Page 1 of New Chimera Project Is Empty

pick a core (none in the cores folder?)

Page 1 is the first page of the New Chimera Project wizard, which opens from File, New Chimera Project. There you pick the core and the machine. An empty Core list means Chimera found no core packages. Chimera ships with no cores and downloads nothing.

Fix. Download a core from its project page on GitHub and put the .chimeraCore file in the Cores folder beside Chimera. On a Mac the folder is ~/Library/Application Support/Chimera/cores. Open Tools, Core Manager to see which folder Chimera reads and what it found. See Quickstart, Method 1 and Core Manager.

A Core I Copied In Is Not in the List

Chimera may be reading a different Cores folder, or the window was open when you copied the file.

Fix. In the Core Manager check the folder on the top line, then press Refresh List. Change folder... points Chimera at another folder. A core that is already loaded stays loaded until you restart Chimera.

Dropping a Game File on the Window Does Nothing Useful

no installed core takes .X files

None of your cores accepts files of that type.

Fix. Find the system on the Systems page, which lists the cores that run it, and install one of them. Some systems want the game packed first, as a disc image or a .zip. See Reproducible Media Maker.

A Saved Project Will Not Open Because Its Core Is Missing

No X core is installed: put its .chimeraCore in the cores folder

The project was made with a core you do not have.

Fix. Install the core it names. To play the movie back the same way, install the exact build that made it. See Keep the build that made a movie.

The Core Cannot Run with This Chimera

The X core here cannot run: Y

A core of that name is installed, but this Chimera cannot run it. The usual cause is a core and a Chimera built far apart, so one expects something the other does not have. The text at the end of the message gives the reason.

Fix. Update Chimera and the core to builds from the same week. The Core Manager shows each core's build date, and Help, About... shows Chimera's. See Menu Options.

The Project Opens with a Different Build of Its Core

the package the project was made with is not here; the newest X is

The exact core build that made the project is gone, so Chimera loaded the newest build of the same core. The movie can desync.

Fix. Put the build that made the project back in the Cores folder. The Core Manager shows each build's date and the short code that names it. Keep old builds that your movies use, because Chimera cannot fetch them again.

A Warning Says Chimera and the Core Were Built Far Apart

This Chimera was built on X and the Y package this project runs on was built on Z - N days apart.

A savestate, a copy of the whole machine at one moment, can change its layout between builds. Saved states may be made again and a branch may refuse to load.

Fix. If anything looks wrong, install the core build from the same week as your Chimera, or update both.

A Core File Is Refused

X is not a core package
the package does not say which systems it runs on (runsOn in its waterbox.config). Get a newer build of the core.

The file is damaged, is not a core, or is too old for this Chimera.

Fix. Download the core again from its project page, and get the newest build. Check that the file ends in .chimeraCore and is for your system, Windows, Linux or macOS.

Can I Get a Core for a System or Game That Has None?

Check the Systems page first, since one core can run many systems. If none runs it, there are two ways.

  • Ask for it. Look for an open request labelled core-request on the Chimera issue list and add to it, or open a new issue that names the emulator and the system.
  • Make it yourself, with an AI agent doing most of the work. See Making a New Core.

Firmware

Which Firmware Does My Core Need?

Each core has a Firmware page in the Cores section. Its Minimal Required Firmware list shows the fewest files most games need, and the Comprehensive Firmware List shows every file with its size and SHA1. The links here go to the DuckStation pages as an example. In Chimera, Config, Firmware... lists the files your installed cores expect and whether each one was found. See the Config menu on Menu Options.

Page 4 of New Chimera Project Asks for Firmware Files

Please indicate where to find the required firmware files.
X: not found in the firmware folder; choose its file

This happens while you create a project with File, New Chimera Project. Page 4 is the last page of that wizard, and it appears only when the machine and settings you chose need firmware that Chimera did not find. Chimera includes no firmware. The files come from hardware you own.

Fix. Choose each file in the list, or use Scan a folder for firmware. To skip this page next time, put the files in the Firmware folder. Set that folder in Config → Paths..., on the Global tab. See Quickstart, Page 4.

A Saved Project Cannot Find Its Firmware

Firmware missing (put it in the firmware folder): X
The firmware this project needs was not found: locate it, or scan a folder

A project records the firmware it uses by name and SHA1, never by where it is on disk. Chimera looked in the Firmware folder and where you chose the file before, and it was not there.

Fix. Put the file in the Firmware folder, or use Locate or the folder scan in the message.

The Firmware Is Not the One the Project Needs

X is not the firmware the project needs: its hash is Y, the project needs Z
the firmware 'X' given is not the one the project pins (pinned Y, given Z): expect the movie to desync

The project recorded the SHA1 of the firmware it was made with, which the message calls pinning. Your file has the same name but different contents, such as a BIOS of another region or version. The movie will most likely desync.

Fix. Use the file whose SHA1 matches. The core's Firmware page lists the SHA1 of each known file, for example the DuckStation list.

The Firmware Window Says a File Is Used Anyway

not the N bytes the core expects - used anyway
right size, a dump the core has never seen - used anyway

Chimera found a file with the right name, but its size or SHA1 is not one the core knows. Chimera still uses it. Games may not start, and other people cannot replay your movie with their own copy.

Fix. Replace it with a file whose size and SHA1 match the core's Firmware page.

Projects and Game Files

The Game Cannot Be Loaded

X could not load this file.

The core named in the message opened the file and refused it. The file may be for another system, damaged, a bad dump, or a format the core does not take.

Fix. Check that the file is for a system the core runs, on the core's Systems page in the Cores section. Try another copy of the game. Some games also need firmware or a setting such as the region. See the core's own Quickstart and Firmware above.

The Game File Cannot Be Found

Some of the project's files were not found beside it: locate them, or scan a folder

A project records the names and SHA1 values of your game files but not where they are. Chimera looks beside the project file first.

Fix. Keep the game files in the same folder as the project, or locate them when asked. See Before you begin.

A Game File Does Not Match Its Recorded Hash

project: 'X' does not match its recorded hash

The file has the right name but different contents. It may be another dump, a patched copy, or a file that changed on disk.

Fix. Use the same file the project was made with. If you meant to use a new file, make a new project with it.

Page 2 of New Chimera Project Refuses a File

X is not one of the formats this slot expects (Y)
X references Y, which is not next to it - a cue's files are added together

Page 2 is the second page of the New Chimera Project wizard, where you add the game files. Each box on it takes certain file types, listed under its heading. A .cue file names the other files of the disc, and those must be in the same folder.

Fix. Add the file to the box whose list includes its type. Keep a .cue and its .bin files together in one folder. If the core takes a disc image and you have a folder of files, pack it with the Reproducible Media Maker.

A Chimera Project Cannot Be Loaded

Cannot open the project

This is the title of the message box. The text under it gives the reason, and other entries on this page explain most of them, such as a missing core, missing firmware or missing game files. Two reasons are about the project file itself.

the file is not a Chimera project (it is not a zip)
this project is in the old form, a single JSON file, which this Chimera does not open: a project is now a zip holding project.json and its inputs

A Chimera project is a .zip file that holds project.json and the inputs. Early builds of Chimera saved a single JSON file, which current builds do not open.

Fix. Open the old file with the Chimera build that made it, or make a new project. A file that is not a zip at all is not a Chimera project.

Chimera Did Not Close Normally the Last Time

Chimera did not close normally the last time this project was open: its unsaved work was kept

Chimera keeps a record of unsaved work while a project is open. After a crash it rebuilt that work.

Fix. Check the movie, then choose Save Project in the File menu. If Chimera crashed, see When nothing here helps.

My Project Is Gone After I Closed Chimera

Creating a project does not save it. It stays in memory until you choose Save Project in the File menu. See After you press Create.

Running a Game

The Game Runs Slowly

Speed depends on the system. Older systems need very little and the newest consoles need a fast PC.

Fix. Compare your PC with Recommended Specs. Try both OpenGL and Vulkan if the core offers both, as the notes there suggest. The greenzone is the set of saved states TAStudio keeps to jump back to earlier frames. It affects speed in two ways.

  • Jumps to earlier frames are slow. The greenzone has too little memory, so it drops states and replays from far back. Give it more in Cache Manager, Greenzone budgets, if the PC has the memory.
  • Playing forward is slow on a heavy core. Saving a state on every frame costs time. Save one in more frames on the Greenzone page.

If none of this helps, the PC is likely too slow for that system. A faster processor helps most cores more than anything else.

There Is Not Enough Memory, or the Game Crashes

there was not enough memory to start the machine
there was not enough memory to save the state

The computer ran out of memory for the machine or for its saved states. When memory runs out, Chimera can also close without a message. The next time you open the project it says it did not close normally and keeps the unsaved work.

Fix. Close other programs. Lower how much memory the greenzone may use in Cache Manager, Greenzone budgets. Newer consoles need a lot of memory. See Recommended Specs. If the game still crashes at the same spot, see When nothing here helps.

The Game's Code Must Be Compiled First

This game's code is not compiled yet: Compile does it.
This game's code was compiled by X, not by this build of the core: Compile does it again.

Some cores, such as RPCS3, translate the console's code for your PC before the game runs. This happens once for each game and core build, on the last page of the New Chimera Project wizard.

Fix. Press Compile and wait until every module is compiled, then press Create. See the RPCS3 Quickstart. Tools, Pre-Compiled Modules... lists what is already compiled. See the Tools menu on Menu Options.

The Computer Ran Out of Memory While Compiling

The computer ran out of memory while compiling. A compile session needs about X GB.

Chimera runs several compile sessions side by side, each counted at a set amount of memory.

Fix. Close other programs and compile again. In Tools, Pre-Compiled Modules..., a larger Memory per compile session runs fewer sessions at once. On Windows, also free space on the system drive, because Windows grows its page file there.

The Core Stops Answering

the core did not finish a frame in X
the core did not finish starting in X

The core took too long for one frame or to start. It may have stopped, or the game may be too heavy for the PC.

Fix. Try again with the core's default settings. If it happens every time at the same spot, report it with the core log. See When nothing here helps.

The Graphics Driver Does Not Offer OpenGL 3.3

the driver would not make an OpenGL 3.3 context
the driver offers OpenGL X, and this needs 3.3

A core that draws with the graphics card needs OpenGL 3.3 or newer.

Fix. Update the graphics driver from the maker of your card. If the core has a software renderer, choose it instead in the Renderer list. That list is on Page 1, the first page of the New Chimera Project wizard, so make a new project with it.

The Picture Looks Different on Another PC

A hardware renderer draws the picture on your graphics card, outside the savestate, so the video can differ from one PC to another. The inputs and the game still match.

Fix. Choose a software renderer when the picture must be the same everywhere, for example for an encode. The Renderer list is on Page 1, the first page of the New Chimera Project wizard.

There Is No Sound

Core is not producing audio

Fix. Click the Sound item on the status bar to turn the core's sound on. See The main window. Check the device and volume in Config, Sound....

Keys or a Gamepad Do Nothing

Fix. Check the bindings in Controllers. If a key is also a hotkey, Key Priority in the Config menu decides which one wins. See Menu Options and Hotkeys. Buttons you press are written into the movie only in recording mode. Q toggles read only. See Playback.

Movies and TAStudio

My Movie Plays Differently than When I Made It

A movie plays back the same only on the same machine. Anything that changes the machine can make it desync.

  • A different core build. See Keep the build that made a movie.
  • Different firmware. See The firmware is not the one the project needs.
  • A different game file. See A game file does not match its recorded hash.
  • Changed project settings. A changed setting makes a different machine, so the game starts again at frame 0.

TAStudio Has Disappeared

TAStudio was hidden, not closed. A project is open exactly when TAStudio is open.

Fix. Click Show TAStudio >> at the right end of the menu bar. See Hide and show TAStudio and Show TAStudio.

Chimera Cannot Go Past the End of the Movie

cannot seek past the movie's end

You asked for a frame after the last frame of the movie.

Fix. Play forward to make the movie longer, or add frames in the piano roll. See Select and edit frames and Playback.

Going to a Frame Replays the Movie from Frame 0

The greenzone was not kept when this project last closed: a graphics card drew the game, and its core does not say its states can be loaded after the project closes. Going to a frame replays the movie from frame 0.

With a hardware renderer, some cores cannot reload saved states after the project closes. Chimera drops them and builds them again as the movie plays.

Fix. Nothing is wrong. Play to the end once and the greenzone is full again. See Greenzone.

A Stored State Is Damaged

the stored state of frame X is damaged (its checksum does not match)

A saved state in the greenzone does not read back correctly, often after a full disk or a crash.

Fix. Choose Edit, Clear Greenzone in TAStudio and play forward again. Edit, State History Integrity Check tests the saved states. See Greenzone.

A Branch or Savestate Will Not Load

This state was written in savestate format X by Y, and this Chimera (Z) ... The machine's layout changed between the two, so the state cannot be loaded; it was not touched.

The state was saved by another build whose machine layout differs. Branches are saved copies of your movie and its state. See Branches.

Fix. Load it with the core build that saved it, or install the core build from the same week as your Chimera.

RAM Watch and RAM Search

A Watch Shows (Not There)

(not there)

The watch's address is past the end of its memory domain. A memory domain is one named area of the machine's memory, such as RAM. A red warning icon at the bottom left of RAM Watch says the same.

Fix. Edit the watch's address, or make it again in the right domain. The domain of a watch cannot be changed. Each core's Memory Domains page lists its domains and sizes, for example Mesen. See RAM Watch, The window.

A Value I Poked Changes Back

The game writes that address again by itself, often on every frame.

Fix. Freeze the address instead, so Chimera writes it again before every frame. See the Watches menu on RAM Watch.

RAM Poke Does Not Support Mixed Types

RAM Poke does not support mixed types

The selected watches have different sizes or display types.

Fix. Select only watches of the same size and type, then poke. See RAM Poke.

An Address Is Refused

"X" is not an address in hex

Fix. Type the address in hexadecimal, using the digits 0 to 9 and the letters A to F. See Go to Address.

RAM Search Runs Out of Memory

Not enough memory for that search
Not enough memory to track the last change of this many addresses

Detailed mode keeps a count for every address, which takes memory on large domains.

Fix. Choose Fast in Options, Mode, or search a smaller memory domain. See RAM Search, Options.

RAM Search Finds Nothing, or Far Too Much

Fix. Follow the rupee example, which narrows a search one change at a time. For a value the game does not show as a number, see Finding a value you cannot see as a number. Check the size and display type too, as some games keep a number in 2 bytes or as decimal digits.

Lua Scripts

Chimera Freezes When a Script Starts

The script loops without handing frames back to the game.

Fix. End each pass of the loop with emu.frameadvance(), or use an event instead. See How a script runs.

while true do
   gui.text(10, 10, "Frame " .. emu.framecount())
   emu.frameadvance()
end

A Script from Another Program Fails with a Nil Value

attempt to index a nil value (global 'savestate')

The script uses a function or library that Chimera does not have. This message is Lua's own, and the name in it changes with the script.

Fix. See Differences from Bizhawk scripts for the usual changes, and Lua References for every function Chimera has.

Colors Drawn by a Script Are Wrong

Chimera writes a color as 0xAARRGGBB, with the see through amount first. Scripts written for 0xRRGGBBAA show the wrong colors. See Differences from Bizhawk scripts.

Drawings Stay on the Picture After a Script Stops

Fix. Press Erase Stale/Stuck Lua Drawing Layers on the Lua Console toolbar. See Lua Console, Toolbar.

A Script Stops Working While Fast Forwarding

Fix. Turn on Run lua scripts when turboing in Customize.

A Script Will Not Start

Unable to access file X

Chimera cannot read the script file. It was moved, renamed or deleted since it was added, often when it comes from Recent Scripts or a saved Lua session.

Fix. Remove it from the list and add it again with Script, Open Script. Inside a script, a file name without a folder is looked for in the script's own folder. See Lua Console, Script menu and Reading and writing files.

The Output Box Stops Showing a Script's Lines

When a script prints too much, the Lua Console stops showing its lines and says so. Print less often, for example once every 60 frames. See Lua Console, The window.

When Nothing Here Helps

  1. Choose Help, Copy Version Info and keep it for the report.
  2. If a core misbehaves, choose Help, Export Core Log... and repeat the problem. See the Help menu on Menu Options.
  3. Choose Help, Report an Issue... to prepare the report. See Report an Issue.
  4. Ask on the ToolAssisted.run Discord.

Never attach games, firmware or keys to a report.
