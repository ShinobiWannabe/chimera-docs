Lua

Basic Examples

The Chimera functions that scripts use most, with a short example for each group and a note on when to use it. The function names and arguments were checked against the Chimera source code. The starting point was the Common Functions script that Bizhawk users know, rewritten for Chimera and for the LuaRocks style guide. A video walks through that script. If the Lua language is new to you, read Basics first.

How a script runs

Chimera runs a script from the Lua Console. See Lua Console for how to open and start one. There are two ways to write a script that works on every frame.

WayHow it looksWhen to use it
A loopwhile true do ... emu.frameadvance() endSimple scripts and anything that follows a plan from one frame to the next. Your code runs, then emu.frameadvance() hands one frame back to the game.
A callbackevent.onframeend(function)Scripts with several small jobs, or jobs that wait for something. Chimera calls your function by itself. See the Events part below.

This is the plan for most scripts on this page. Functions do the work, and the loop at the bottom calls them once per frame.

local function show_hud()
   gui.text(10, 10, "Frame " .. emu.framecount())
end

while true do
   show_hud()
   emu.frameadvance()
end
FunctionWhat it doesWhen to use it
emu.frameadvance()Lets the game run for one frame, then returns to the script.At the end of every loop. A loop without it freezes Chimera.
emu.framecount()The number of the current frame.To label output and to act on a certain frame.
emu.islagged()True when the game did not read the controller this frame.To find frames where input has no effect.
emu.getsystemid(), emu.getcorename()The system and core that are running.To make one script serve several systems.

A script that uses a function from another program, such as Bizhawk, may fail with a message that a value is nil. This usually means the function is not in Chimera. See the end of this page for the known differences.

Showing messages

FunctionWhat it doesWhen to use it
console.log(...)Writes its values on one line in the Output box of the Lua Console. It accepts several values and tables.Checking a value while you write a script.
console.writeline(text), console.write(text)Writes a line, or text without a line break.Building a line from several parts.
console.clear()Empties the Output box.At the start of a script that prints a lot.
gui.addmessage(text)Shows a message on the game screen, in the area where Chimera shows its own messages.Telling the person running the script that something happened.
console.clear()
console.log("Frame", emu.framecount(), "lag", emu.lagcount())
gui.addmessage("Script started")

Reading and writing memory

Memory is where the game keeps lives, positions, timers and everything else. A script finds an address with the RAM Search and the Hex Editor tools, and then reads it every frame.

Memory domains

A memory domain is one block of memory that a core exposes, such as the main RAM or the video RAM. Each core has its own list. The mainmemory functions use the main memory of the core. The memory functions use the domain you pick.

FunctionWhat it doesWhen to use it
mainmemory.getname()The name of the main memory domain.To print or pass to the memory functions.
memory.getmemorydomainlist()Every domain of this core, as one text with a line for each.To learn which domains a core has.
memory.usememorydomain(name)Picks the domain that memory functions use. Returns false when the name is wrong.Once, near the top of a script.
memory.getcurrentmemorydomain()The domain now in use.To check what a script is reading.
console.log(memory.getmemorydomainlist())
console.log("Main memory is " .. mainmemory.getname())

if not memory.usememorydomain("WRAM") then
   console.log("This core has no WRAM domain")
end

Reading values

The name of a read function tells its size and byte order. Pick the one that matches how the game stores the value.

Part of the nameMeaning
u8 u16 u24 u32Unsigned. The value is 0 or more. A u8 is 0 to 255.
s8 s16 s24 s32Signed. The value can be negative. An s8 is -128 to 127.
_leLittle endian. The low byte is first in memory. The NES, SNES, Game Boy, GBA and PlayStation are like this.
_beBig endian. The high byte is first. The Genesis and the Nintendo 64 are like this.
readfloatA decimal number stored as a float.
readbyteThe same as read_u8.
local lives = mainmemory.read_u8(0x0359)
local speed = mainmemory.read_s8(0x0361)
local x_position = mainmemory.read_u16_le(0x0362)
local score = mainmemory.read_u32_be(0x0370)

-- the same read on a named domain
local from_wram = memory.read_u8(0x0100, "WRAM")

To read many bytes, one call is much faster than many calls.

FunctionReturns
mainmemory.readbyterange(address, length)A table that starts at 0.
mainmemory.read_bytes_as_array(address, length)A table that starts at 1, which fits ipairs and #.
mainmemory.read_bytes_as_binary_string(address, length)One text that holds the raw bytes.
local bytes = mainmemory.read_bytes_as_array(0x0100, 64)
local total = 0
for _, value in ipairs(bytes) do
   total = total + value
end
console.log("Sum of 64 bytes " .. total)

Writing values

Replace read with write in any read function and add the new value as the last argument.

mainmemory.write_u8(0x0359, 9)
mainmemory.write_u16_be(0x0362, 500)
mainmemory.write_bytes_as_array(0x0100, {0xAB, 0x12, 0xCD, 0x34})

A memory write is not stored in the movie. A movie that depends on a write will not play back the same way on its own. Use writes to test an idea, then enter the real input in TAStudio.

Working with bits

Games often pack several yes or no values into one byte. The bit library reads and changes single bits. Bit 0 is the rightmost bit.

FunctionWhat it doesWhen to use it
bit.check(value, position)True when the bit is on.Reading one flag.
bit.set(value, position), bit.clear(value, position)Gives the value with that bit turned on, or off.Changing one flag before writing it back.
bit.band(a, b), bit.bor(a, b), bit.bxor(a, b)And, or and exclusive or.Keeping, adding or flipping groups of bits with a mask.
bit.lshift(v, n), bit.rshift(v, n)Move bits left or right.Taking one part out of a byte.
bit.bnot(v)Flips every bit.Building a mask.
bit.byteswap_16, bit.byteswap_32Swap the byte order.Turning big endian into little endian.
local flags = mainmemory.read_u8(0x0400)

if bit.check(flags, 3) then
   console.log("Bit 3 is on")
end

flags = bit.set(flags, 0)
flags = bit.clear(flags, 7)
mainmemory.write_u8(0x0400, flags)

local high_nibble = bit.rshift(bit.band(flags, 0xF0), 4)
console.log("High nibble " .. high_nibble)

Drawing on the screen

Drawings are made in the coordinates of the game picture, where 0, 0 is the top left corner. A drawing lasts one frame, so draw again on every frame. A color can be a name such as "red", a text such as "#FF8800", or a number written as 0xAARRGGBB. AA is the see through amount, where FF is solid.

FunctionWhat it doesWhen to use it
gui.text(x, y, text, color, anchor)Quick text. The anchor can be topleft, topright, bottomleft or bottomright.Most text. It is much faster than the others.
gui.drawString(x, y, text, color, back, size, font, style)Text with a size, font, style and background. gui.drawText is the same function.When the look of the text matters.
gui.drawLine(x1, y1, x2, y2, color)A line between two points.Arrows, guides and paths.
gui.drawRectangle(x, y, width, height, line, fill)A rectangle from a corner and a size.Boxes where you know the size.
gui.drawBox(x1, y1, x2, y2, line, fill)A rectangle from two corners.Boxes where you know both corners.
gui.drawEllipse, gui.drawPie, gui.drawPixelAn ellipse, a slice of a circle and one dot.Hit circles and markers.
gui.drawImage(path, x, y, width, height, cache)A picture from a file. A relative path starts in the script's folder. Cached by default.Icons and custom graphics.
gui.clearGraphics()Removes drawings now.When a script stops drawing for a while.
gui.text(10, 10, "Lives " .. mainmemory.read_u8(0x0359))
gui.drawString(10, 30, "Large text", 0xFFFF0000, nil, 16)
gui.drawLine(0, 60, 100, 60, "white")
gui.drawRectangle(10, 70, 100, 20, 0xFF00FF00, 0x8000FF00)
gui.drawBox(10, 100, 110, 120, "yellow")
gui.drawImage("feather.png", 64, 130, 18, 24, false)

To keep text off the game picture, ask for extra space around it and draw there. client.SetGameExtraPadding(left, top, right, bottom) adds black space on the left, top, right and bottom of the game surface.

client.SetGameExtraPadding(0, 0, 120, 0)

local function draw_side_panel()
   local x_position = client.bufferwidth() + 8
   gui.text(x_position, 10, "Side panel")
end

The window and the emulator

FunctionWhat it doesWhen to use it
client.screenwidth(), client.screenheight()Size in pixels of the drawing area.Placing text relative to the edges.
client.bufferwidth(), client.bufferheight()Size of the game picture without padding.Placing things in the padding.
client.pause(), client.unpause(), client.togglepause(), client.ispaused()Pause the game, resume it and ask if it is paused.Stopping on a condition so you can look.
client.speedmode(percent)Sets the speed.Fast forward through a boring part.
client.screenshot(path)Saves a picture of the screen.Capturing a state when something happens.
client.getversion()The commit that identifies this Chimera build.Printing it in a bug report.
local function pause_when_dead()
   if mainmemory.read_u8(0x0359) == 0 then
      client.pause()
      gui.addmessage("Paused. No lives left")
   end
end

Reading the keyboard and the mouse

input.get() returns the keys and buttons on your computer that are held now. It is not the game controller.

FunctionWhat it doesWhen to use it
input.get()A table with an entry for each key held.Starting an action from a key you pick.
input.getmouse()A table with X, Y, Left, Middle and Right.Clicking on the game to pick a position.
local keys = input.get()
if keys["Space"] then
   gui.addmessage("Space is down")
end

local mouse = input.getmouse()
gui.text(10, 200, "Mouse " .. mouse.X .. ", " .. mouse.Y)

Reading the controller

FunctionWhat it returnsWhen to use it
joypad.get(controller)The input of this frame as the movie sees it.Showing what the movie presses.
joypad.getwithmovie(controller)The input the core will get, including the movie input.Checking what the game really received.
joypad.getimmediate(controller)What you are holding now.Reacting to the person at the keyboard or pad.

Without a controller number the names carry the player, such as P1 Right. With a number the names are plain, such as Right. Print them once to learn the names a core uses.

for name, value in pairs(joypad.get()) do
   console.log(name, value)
end

local pad_one = joypad.get(1)
if pad_one["Right"] then
   gui.text(10, 10, "Holding right")
end

Writing inputs

There are three ways to put input into a run. They suit different jobs.

WayWhat it changesWhen to use it
joypad.set and its relativesThe input the core receives on the current frame only.A script that plays the game, such as a bot, or that adds a button to what you press. Call it again each frame.
tastudio.submitinputchange and its relativesAny frame of the TAStudio movie.Writing a stretch of input into the movie, from a plan or from a file.
movie.getinput and its relativesNothing. They read the movie.Checking or copying what is already in the movie.

Setting the controller for this frame

FunctionWhat it does
joypad.set(buttons, controller)Sets buttons from a table of true and false. A button that is left out of the table is not changed.
joypad.setfrommnemonicstr(line)Sets every button from one line of text written like a line in the movie input log. Read a line with movie.getinputasmnemonic(frame) to see the layout for a core.
joypad.setaxis(name, value, controller)Sets one analog control, such as a stick, for this frame.
joypad.setanalog(table, controller)Sets analog controls and keeps them held until cleared. Use an empty text as the value to let go.
-- with a controller number the names have no player prefix
local function hold_right_and_jump()
   joypad.set({Right = true, A = true}, 1)
end

-- without one, give the full names
local function hold_right_and_jump_full_names()
   joypad.set({["P1 Right"] = true, ["P1 A"] = true})
end

local function tilt_stick()
   joypad.setaxis("Stick X", 80, 1)
end

while true do
   hold_right_and_jump()
   emu.frameadvance()
end

joypad.set lasts one frame, so call it on every frame, as the loop above does. While TAStudio is recording, check the result in the piano roll before you rely on it. To place input in a chosen frame of the movie, use the TAStudio functions below.

Writing inputs into the TAStudio movie

These functions work on the open TAStudio project. First queue the edits, then apply them together. All the edits become one step that the Undo button of TAStudio can take back. They do nothing when TAStudio is not open, so test tastudio.engaged() first.

FunctionWhat it does
tastudio.submitinputchange(frame, button, state)Queues a button held (true) or released (false) on a frame.
tastudio.submitanalogchange(frame, name, value)Queues a value for an analog control.
tastudio.submitinsertframes(frame, count)Queues blank frames inserted before a frame.
tastudio.submitdeleteframes(frame, count), tastudio.submitclearframes(frame, count)Queues frames removed, or frames emptied of input.
tastudio.applyinputchanges()Applies everything queued, as one step.
tastudio.clearinputchanges()Throws away what is queued.

Frames are counted from 0 as in the piano roll. Queued edits are shared by all running scripts. These functions cannot be used from inside an input or memory callback.

local function hold_button(button, first_frame, last_frame)
   if not tastudio.engaged() then
      console.log("Open TAStudio first")
      return false
   end
   for frame = first_frame, last_frame do
      tastudio.submitinputchange(frame, button, true)
   end
   tastudio.applyinputchanges()
   return true
end

hold_button("P1 A", 100, 110)

Reading the movie

FunctionWhat it doesWhen to use it
movie.length()The number of frames in the movie.Looping over the whole movie.
movie.getinput(frame, controller)A table of the buttons held on a frame.Checking input before changing it.
movie.getinputasmnemonic(frame)One frame as a line of text.Writing the movie to a file, or copying a frame.
movie.mode()PLAY, RECORD, FINISHED or INACTIVE.Doing something only while recording.
movie.isloaded(), movie.filename()Whether a movie is loaded, and its file.Guarding a script.
movie.save(name)Saves the current movie. A name without a path goes in the movie folder. A file that exists is not replaced.Making a backup copy from a script.
local function count_frames_with(button)
   local total = 0
   for frame = 0, movie.length() - 1 do
      if movie.getinput(frame)[button] then
         total = total + 1
      end
   end
   return total
end

console.log("A is held on " .. count_frames_with("P1 A") .. " frames")

Saving and loading game state

Older Bizhawk scripts call savestate.saveslot and savestate.loadslot. Chimera does not have a savestate library. Use one of these instead.

ToolWhat it isWhen to use it
memorysavestateA state kept in memory and picked by an identifier. It holds only the core data, not the movie input.Trying something many times from one point in a single script run.
TAStudio branchesA saved copy of the input and the game state. See the next part.Keeping work you may want back, in the project file.
The greenzoneThe states TAStudio keeps by itself so that it can jump to any frame.Nothing to do. tastudio.hasstate(frame) checks whether a frame has one.
FunctionWhat it does
memorysavestate.savecorestate()Saves the core state and returns an identifier.
memorysavestate.loadcorestate(id)Loads the saved state.
memorysavestate.removestate(id), memorysavestate.clearstatesfrommemory()Frees one state, or all of them.
local checkpoint = memorysavestate.savecorestate()

local function return_to_checkpoint()
   memorysavestate.loadcorestate(checkpoint)
end

event.onexit(function()
   memorysavestate.removestate(checkpoint)
end)

Saving and loading branches

A branch is a saved copy of the movie input up to a frame, with the game state at that frame. See Branches for how to use them by hand. A script can load, list, name and watch branches. A script cannot create one. To save a branch, press Add in the Branches box or press Alt+Insert. Branches are kept in the TAStudio project when you save it.

FunctionWhat it doesWhen to use it
tastudio.getbranches()A table that starts at 0. Each entry has Id, Frame and Text.Listing branches or finding one by its name.
tastudio.loadbranch(index)Loads the branch with that number, counted from 0.Going back to a saved attempt.
tastudio.setbranchtext(text, index)Names a branch. Without an index it names the next branch that gets saved.Labeling a branch before you press Add.
tastudio.get_branch_index_by_id(id)The index of the branch with this Id, or nil.Finding a branch that has moved.
tastudio.getbranchinput(id, frame)The input of a frame inside a branch.Comparing a branch with the movie.
tastudio.onbranchsave(fn)Runs your function after a branch is created or updated. It gets the index.Reacting when you save a branch.
tastudio.onbranchload(fn), tastudio.onbranchremove(fn)The same for a load and for a removal.Logging branch use.

# does not count item 0, so walk a branch table from 0 until an entry is missing.

local function find_branch(text)
   local branches = tastudio.getbranches()
   local index = 0
   while branches[index] do
      if branches[index].Text == text then
         return index
      end
      index = index + 1
   end
   return nil
end

local index = find_branch("before the boss")
if index then
   tastudio.loadbranch(index)
else
   console.log("No branch has that name")
end

To save a branch with a name, set the name first and then add the branch by hand. This script also writes a line to a file each time you save one.

tastudio.setbranchtext("before the boss")

tastudio.onbranchsave(function(index)
   local branch = tastudio.getbranches()[index]
   local file = assert(io.open("branches.txt", "a"))
   file:write(index, ",", branch.Frame, ",", branch.Text, "\n")
   file:close()
end)

tastudio.loadbranch cannot be used inside an input or memory callback. Call it from the main part of the script.

Reading and writing files

Scripts read and write files with the io library that comes with Lua. A path without a folder, such as "results.txt", is in the same folder as the script. Use forward slashes in longer paths. Always close a file when you are done.

CallWhat it doesWhen to use it
io.open(path, "w")Opens a file for writing. An old file of that name is replaced.Saving a fresh result.
io.open(path, "a")Opens a file for adding to the end.A log that grows.
io.open(path, "r")Opens a file for reading. Gives nil and a message when it fails.Loading settings or a plan.
file:write(...), file:close()Writes values and closes the file.Every file you open.
file:lines(), file:read("a")Reads line by line, or the whole file as one text.Loading a list, or a small file.
local function write_lines(path, lines)
   local file, err = io.open(path, "w")
   if not file then return nil, err end
   for _, line in ipairs(lines) do
      file:write(line, "\n")
   end
   file:close()
   return true
end

local function read_lines(path)
   local file, err = io.open(path, "r")
   if not file then return nil, err end
   local lines = {}
   for line in file:lines() do
      table.insert(lines, line)
   end
   file:close()
   return lines
end

write_lines("notes.txt", {"first line", "second line"})
local lines = read_lines("notes.txt")
console.log(#lines .. " lines read")

A log that follows the game is a common use. This one writes the position on every frame to a file that opens in a spreadsheet, and closes the file when the script stops.

local log_file = assert(io.open("positions.csv", "w"))
log_file:write("frame,x,y\n")

local function log_position()
   local x_position = mainmemory.read_u16_le(0x0362)
   local y_position = mainmemory.read_u16_le(0x0364)
   log_file:write(string.format("%d,%d,%d\n", emu.framecount(), x_position, y_position))
end

event.onframeend(log_position)
event.onexit(function()
   log_file:close()
end)

A file can also drive the movie. This reads a plan where each line holds a frame, a button and true or false, and writes it into TAStudio.

-- plan.txt holds lines such as
-- 100 P1 A true
-- 110 P1 A false
local function apply_plan(path)
   local file, err = io.open(path, "r")
   if not file then
      console.log("Cannot open " .. path .. " - " .. err)
      return false
   end
   for line in file:lines() do
      local frame, button, state = line:match("^(%d+)%s+(.-)%s+(%a+)$")
      if frame then
         tastudio.submitinputchange(tonumber(frame), button, state == "true")
      end
   end
   file:close()
   tastudio.applyinputchanges()
   return true
end

apply_plan("plan.txt")

The reverse works too. This writes the whole movie to a file, one line for each frame, in the text form the movie log uses.

local function export_movie(path)
   local file, err = io.open(path, "w")
   if not file then return nil, err end
   for frame = 0, movie.length() - 1 do
      file:write(movie.getinputasmnemonic(frame), "\n")
   end
   file:close()
   return true
end

export_movie("movie-input.txt")

Events

An event function tells Chimera to call your function when something happens. Each one returns an identifier, which you can pass to event.unregisterbyid to stop it. Give a name as the last argument to find it in the Registered Functions list of the Lua Console.

FunctionYour function runsWhen to use it
event.onframestart(fn), event.onframeend(fn)At the start or the end of every frame.Per frame jobs with no loop.
event.oninputpoll(fn)Each time the core reads the controller.Changing input at the last moment.
event.onmemoryread(fn, address), event.onmemorywrite(fn, address)Just before the core reads or writes an address.Finding the code that touches a value.
event.onmemoryexecute(fn, address)Just before the core runs the code at an address.Following what the game does at one point.
event.onexit(fn)After the script stops.Closing files.
local lives_address = 0x0359

local function on_lives_write(address, value)
   console.log("Lives written at frame " .. emu.framecount() .. " value " .. value)
end

local callback_id = event.onmemorywrite(on_lives_write, lives_address, "lives watch")

event.onexit(function()
   event.unregisterbyid(callback_id)
end)

Memory callbacks run very often. Keep the function short, and use event.unregisterbyid to stop them when they are not needed.

Putting it together

This script shows a small display, holds right, and jumps when you press the space bar. It is the old Common Functions script reduced to its useful parts and written for Chimera. Change the addresses for your game.

local LIVES_ADDRESS = 0x0359
local X_ADDRESS = 0x0362

local function draw_hud()
   local lives = mainmemory.read_u8(LIVES_ADDRESS)
   local x_position = mainmemory.read_u16_le(X_ADDRESS)
   gui.text(10, 10, "Lives " .. lives)
   gui.text(10, 26, "X " .. x_position)
   gui.drawRectangle(8, 8, 90, 34, "white")
end

local function is_space_down()
   return input.get()["Space"] == true
end

local function drive()
   if is_space_down() then
      joypad.set({Right = true, A = true}, 1)
   end
end

while true do
   draw_hud()
   drive()
   emu.frameadvance()
end

Differences from Bizhawk scripts

Old scripts need a few changes before they run here.
