RPCS3

Options

Settings the RPCS3 core exposes in the New Project wizard. Click a column heading to sort. Click again to reverse.

Settings

50 of 50
Rendereropengl-hwopengl-hwRPCS3 has one renderer: its own OpenGL renderer, drawing on your computer's real graphics card. The graphics card is outside the core and is different on every computer. Pictures that a game reads back from the renderer end up in the game's memory, so a movie recorded this way plays back only with the same graphics driver. On a computer that offers no OpenGL, the core draws nothing and says so.
Write color buffers to memorytrue, falsefalseThe RSX (the PS3's graphics chip) draws into buffers that are also in the console's memory, and on a real PS3 a game can read them back at any time. This setting makes the renderer write every finished color buffer back into that memory, as the console does. It is off by default, as in RPCS3 itself. Most games never read their own picture, and copying every buffer back on every frame is expensive. With it on, Resident Evil 5 ran out of memory (16 GiB) within thirty frames, and with it off the game runs. Turn it on for a game that reads the screen back. The sign of such a game is a picture, made by the game from its own screen, that comes out black or out of date. Oblivion draws the thumbnail of a saved game this way, and without this setting the icon is black in the exported save and in the game's own load menu. This is not only a display option, because a game that reads those pixels can act on them. It is part of the machine, so a movie needs the same value.
Read color buffers from memorytrue, falsefalseThe opposite direction of 'Write color buffers to memory'. Before drawing over a buffer, the RSX (the graphics chip) loads what the console's memory already holds for it, as the console does. A game that draws on top of a buffer it filled earlier in another way needs this, and without it that earlier content is missing. It is off by default, as in RPCS3 itself, for the same reason as the write setting: most games never do this, and the copy takes time. This is not only a display option, because the pixels it brings in were drawn by the game and the game can use them. It is part of the machine, so a movie needs the same value.
ZCULL accuracyPrecise, Approximate, RelaxedPreciseHow exactly the counts of visible pixels (the ZCULL statistics of the RSX, the PS3's graphics chip) are reported back to the game. 'Precise' counts every sample and waits for the graphics card. 'Approximate' and 'Relaxed' answer sooner with a less exact count. Some games need that to run at all, and some draw wrongly with it. It is part of the machine, so a movie needs the same value.
Resolution scale threshold1 to 102416Render targets (the surfaces a game draws into) smaller than this many pixels on each side are never scaled by 'Resolution scale'. The RPCS3 wiki writes the value in the form '320x320'. Here it is just the one number. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing.
FramelimitOff, 30, 50, 60, 120, Display, Auto, PS3 Native, InfinitePS3 NativeHow RPCS3 times flips, the moments a finished picture is shown. 'PS3 Native' holds a flip that waits for vertical sync until the console's next vertical blank, as the hardware does. A rate (60, Auto and so on) holds a flip that comes early until its turn in the same way, and the RSX (the graphics chip) keeps reading commands in the meantime. RPCS3 itself pauses the RSX thread there. In this core that pause is the machine's own time, and it stopped Mortal Kombat (chimera#125) and made Rayman Legends run out of memory (chimera#165). 'Off' and 'Infinite' flip immediately. It is part of the machine, so a movie needs the same value.
Sleep timers accuracyAs Host, Usleep Only, All TimersAs HostHow precisely the console's sleep and timer calls are followed. The finer choices wake threads exactly on time and are slower. It is part of the machine, so a movie needs the same value.
Vblank rate1 to 600060How many vertical blank (vblank) events the console sees each second. Games that time themselves by vblank run faster at a higher rate, and some run correctly only at 120. This core fixes it so that a movie gives the same result every time, and the default is that fixed value. Chimera decides when each frame runs, so changing it is an experiment, and a movie needs the same value.
VBlank NTSC Fixuptrue, falsefalseMakes the vblank rate 59.94 instead of 60, as on an NTSC console. This core fixes it so that a movie gives the same result every time, and the default is that fixed value. Chimera decides when each frame runs, so changing it is an experiment, and a movie needs the same value.
Multithreaded RSXtrue, falsefalseMoves part of the work of the RSX (the graphics chip) to another thread. That thread is scheduled like every other thread in the machine, and the order in which the two finish can differ. This core fixes it so that a movie gives the same result every time, and the default is that fixed value. Chimera decides when each frame runs, so changing it is an experiment, and a movie needs the same value.
Disable vertex cachetrue, falsefalseStops RPCS3 from reusing vertex data it has already sent to the graphics card. It is for games that change that data in place. It is part of the machine, so a movie needs the same value.
Strict rendering modetrue, falsefalseFollows the rules of the RSX (the graphics chip) exactly where RPCS3 normally takes faster shortcuts. It is slower, and it is correct for games that the shortcuts break. It is part of the machine, so a movie needs the same value.
Firmware librariesAny textSystem libraries to run from the PS3 system software (LLE) instead of RPCS3's own versions (HLE), separated by commas, for example 'libvdec.sprx'. The RPCS3 wiki names a library when RPCS3's version of it is not good enough for a game. libvdec.sprx is the video decoder. This needs the system software. Without it there is nothing to run the libraries from, and the setting is ignored. It is part of the machine, so a movie needs the same value.
Accurate RSX reservation accesstrue, falsefalseMakes the RSX (the graphics chip) respect the Cell processor's memory reservations exactly when it reads and writes shared memory. It is part of the machine, so a movie needs the same value.
SPU block sizeSafe, Mega, GigaSafeHow much SPU code the recompiler compiles as one unit. Larger blocks are faster. They also change the points where the recompiler counts time (once per function and loop), so the machine's clock runs slightly differently. It is part of the machine, so a movie needs the same value.
SPU xfloat accuracyAccurate, Approximate, Relaxed, InaccurateApproximateHow exactly the SPU processors' non-standard floating point is reproduced. Choose 'Accurate' for games whose physics or animation go wrong. It is part of the machine, so a movie needs the same value.
Handle RSX memory tilingtrue, falsefalseEmulates the RSX's tiled memory layout when the Cell processor reads or writes a tiled region. It is for games that draw from or into such a region directly. It is part of the machine, so a movie needs the same value.
Force CPU blit emulationtrue, falsefalseDoes the RSX's image copies on the processor, into the console's memory, instead of on the graphics card. It is for games that read the result back. It is part of the machine, so a movie needs the same value.
Anti-aliasingDisabled, AutoAutoWhether the render targets a game asks to be multisampled really are. 'Disabled' draws them without multisampling, which some games need to show anything at all. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing.
Write depth buffertrue, falsefalseWrites finished depth buffers back into the console's memory, where a game that reads them expects them. It is the depth version of 'Write color buffers to memory'. It is part of the machine, so a movie needs the same value.
Read depth buffertrue, falsefalseBefore drawing into a depth buffer, loads what the console's memory already holds for it. It is part of the machine, so a movie needs the same value.
Resolution scale25 to 800100Draws at this percentage of the game's own resolution. The picture Chimera receives changes size with it. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing.
Driver wake-up delay0 to 166670How many microseconds the RSX thread waits before it wakes up to process new commands. It is for games that depend on the exact timing of their own command stream. It is part of the machine, so a movie needs the same value.
Shader qualityAuto, Low, High, UltraHighThe floating point precision used by the shaders on your graphics card. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing.
Allow Host GPU Labelstrue, falsefalseLets your graphics card signal the RSX's semaphores directly, instead of through RPCS3's own synchronisation. It is part of the machine, so a movie needs the same value.
Disable ZCull occlusion queriestrue, falsefalseAnswers every occlusion query (the question whether something is visible) with yes, without asking the graphics card. It is part of the machine, so a movie needs the same value.
Emulate Special Depth Comparisontrue, falsefalseReproduces the RSX's depth comparison where it differs from the graphics card's. It is for shadows and decals that flicker or disappear. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing.
Shader modeLegacy Recompiler (single-threaded), Async Recompiler (multi-threaded), Async Recompiler with Shader Interpreter, Shader Interpreter onlyLegacy Recompiler (single-threaded)How the shaders for your graphics card are made. This core compiles each shader on the RSX thread before drawing with it. The asynchronous modes draw without a shader until one is ready, so what is drawn depends on how fast your computer compiles. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing. This core fixes it so that a movie gives the same result every time, and the default is that fixed value. Preferred SPU threads0 to 60How many SPU threads may run heavy work at the same time. 0 leaves it to RPCS3. It is part of the machine, so a movie needs the same value.
Accurate SPU DMAtrue, falsefalseMakes every SPU memory transfer (DMA) exactly as indivisible as it is on the hardware. It is part of the machine, so a movie needs the same value.
Default resolution1920x1080, 1920x1080i, 1280x720, 720x480, 720x480i, 720x576, 720x576i, 1600x1080, 1440x1080, 1280x1080, 960x10801280x720The video mode the console reports to the game as the mode of its display. A game chooses its own rendering resolution from it, so it changes what the game does and not only what is shown. It is part of the machine, so a movie needs the same value.
Maximum SPURS threads1 to 66The largest number of SPU threads a SPURS task group may run at once. It is part of the machine, so a movie needs the same value.
RSX FIFO accuracyFast, Atomic, Ordered & Atomic, PS3AtomicHow the RSX reads the command stream that the Cell processor writes. The stricter modes see each command exactly as and when the console's chip would. It is part of the machine, so a movie needs the same value.
Delay each odd MFC Commandtrue, falsefalseDelays every second SPU memory transfer (DMA) command so that the commands finish out of order, which some games depend on. RPCS3 chooses the order from the processor's time-stamp counter. It is part of the machine, so a movie needs the same value.
Disable SPU GETLLAR Spin Optimizationtrue, falsefalseStops RPCS3 from taking a shortcut for SPUs that wait in a loop on a memory reservation. It is part of the machine, so a movie needs the same value.
Debug console modetrue, falsefalseMakes the console a debug unit, with the larger memory that model has, for games that need it. It is part of the machine, so a movie needs the same value.
Accurate PPU 128 reservations-1 to 140How long a loop on a 128-byte PPU memory reservation may be and still be made exact. 0 means never and -1 means always (the wiki's 'Always Enabled'). It is part of the machine, so a movie needs the same value.
PPU thread count1 to 82How many PPU threads may run at once. The console has two hardware threads. LOD bias offset-32 to 320.0A number added to every texture's level-of-detail bias. Negative is sharper and positive is blurrier. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing.
Enable SPU loop detectiontrue, falsefalseDetects SPUs that wait in a loop and lets another thread run. This core fixes it so that a movie gives the same result every time, and the default is that fixed value. Chimera decides when each frame runs, so changing it is an experiment, and a movie needs the same value.
Anisotropic filterAuto, 2x, 4x, 8x, 16xAutoOverrides the game's anisotropic filtering. 'Auto' keeps the game's own. It changes what your graphics card draws, not what the console calculates. Without a renderer on a graphics card it does nothing.
SPU Decoderasmjit, interpreterasmjitHow the code of the SPU processors is run. 'asmjit' is RPCS3's ASMJIT recompiler. It gives the same results several times faster, and it counts the machine's time once per loop pass and function entry. 'interpreter' counts time per instruction. Both give the same result every time, but their clocks run slightly differently, so a movie plays back only with the decoder it was recorded with.
PPU Decoderinterpreter, llvminterpreterHow the code of the main processor (PPU) is run. 'interpreter' counts the machine's time per instruction. 'llvm' is RPCS3's LLVM recompiler. Every module is compiled inside the core when it loads, in every session (about ten seconds for the system software's liblv2, and minutes for a big game with its libraries), and then runs many times faster. Compiled code counts time per basic block. Both give the same result every time, but their clocks run slightly differently, so a movie plays back only with the decoder it was recorded with. The interpreter is the default until compiled modules can be kept between sessions.

About this data

50 settings, 50 rows. There is one row for each machine and each option. A setting for several machines is repeated for each machine. A setting with no rule is listed under every machine as 'Always shown'. Origin says where the setting came from.
