RPCS3

Full Guide

System PlayStation 3

Before you begin

  • A core is the package that holds an emulator. This page uses the RPCS3 core, which runs PlayStation 3. You get it from the Releases page of the chimera-core-rpcs3 repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A savestate is a copy of the whole machine at one moment. You can return to it later.
  • A recompiler (also called a JIT) translates the console's code into your computer's code before running it, which is fast. An interpreter reads the console's code one step at a time, which is slower.
  • HLE and LLE are two ways to copy a console's built-in software. HLE replaces it with new code and LLE runs the real thing.
  • A frame is one picture the game draws. A game draws many of them each second.

Page 1 Choose the core

The first page asks you to pick a core, either an emulator or a game. Everything on the later pages depends on this choice.

OptionWhat it does
KindEmulator or Game. It decides which cores the Core list shows. RPCS3 is an emulator. The wizard opens on the kind you used last, when you have cores of that kind installed.
CoreLists the installed cores of that kind. Each line shows the core name, its version date and the systems it runs. Choose the RPCS3 line. If you have two builds of one core installed, the line also shows the first eight characters of the package's fingerprint in square brackets.
SystemNames the machine to emulate. RPCS3 has one, PlayStation 3, so the box is greyed out.
RendererChooses how the picture is drawn. The choices are Hardware (OpenGL), Hardware (Vulkan). The default is Hardware (Vulkan). A Hardware choice uses your graphics card. It is fast, but the picture is drawn outside the savestate, so video can differ on another computer. A warning appears under the box when you pick one.

A link at the bottom takes you to the Chimera issue page, for reporting problems and asking for features. If no core is installed, Next shows a message asking you to pick one.

Page 2 Add your files

This page asks for the game files and other data. The core decides what appears here. RPCS3 shows 5 groups of files. Hover over a group to see the core's own help text.

GroupHow manyFile typesWhat it is for
GameExactly one.elf, .self, .bin, .iso, .zip, .7z, .pkgThe game. It is one of four things. (1) A PS3 executable (.elf, .self), started directly as a modified console would start it. (2) A disc image (.iso). This is either a decrypted image, or a Redump image with its disc key given under Disc key. (3) A disc copied as a FOLDER and packed into a single .zip or .7z. The archive is read in place and never unpacked, so it may be as large as the disc. Store the files in it without compression, so that the game's big files can be read at any position. A disc game's EBOOT.BIN alone is not enough, because the game's data is in the rest of the disc. A .7z works the same way, but it must be packed NON-SOLID - `7z a -ms=off`. By default 7-Zip packs all files into one shared stream, which has to be decoded from its start to reach anything in it. Reading the first 64 KB of one disc's EBOOT.BIN took 190 seconds that way. A solid archive is therefore refused, so that it cannot look as if the program has stopped responding. (4) The .pkg of a title sold only as a download and never on a disc. It is installed on the console's hard disk before the machine starts, exactly as the console's own menu (XMB) installs it, and the machine starts what the installation produced. No disc and no disc key are involved. A package that is content FOR a game (downloadable content, a licence, a patch for a disc game) is refused here by name. It belongs under Packages.
Disc keyAt most one.dkey, .keyShown when the file under Game does not end in .pkg.
The 32-character disc key that decrypts a Redump PS3 image (the .dkey file distributed with it). It is not needed for a decrypted image or a homebrew executable. A package game does not need one either, because a .pkg contains no encrypted disc.
PackagesAny number.pkgPS3 package files (.pkg) that are installed on the console's hard disk before the machine starts, the way the console's own menu (XMB) installs them - downloadable content, game patches and unlock packages. Any number can be given, and they are installed in the order listed. Encrypted content (EDAT) also needs its licence. A .rap licence comes as a package of its own, and a package that was repacked to need no licence installs and works alone. The project and the movie record exactly which packages they were, so a movie that plays a game with its downloadable content can be played back by anyone who has the same files. A file that is not a PS3 package, or a patch for another version of the game, is refused, so that content is never silently missing.
LicencesAny number.rapThe account licence (.rap) for a PlayStation Store title that was paid for. A purchased package is protected (NPDRM) - its executable and its data are encrypted, and the key is this 16-byte file. The console keeps it in the user's exdata folder and looks it up BY NAME, so the file's name is the content id and must not be changed. Give one for each package that needs it, and the machine decrypts and starts what it unlocks. Without it a licensed game stops at 'failed to decrypt content'. A free package (a demo, or a repack that needs no licence) needs none. The project and the movie record exactly which file it was, as they do for every other file the machine starts with. File names. A .rap file is named after the content it unlocks, and the console finds it by that name, for example UP9000-NPUA80134_00-ECHOCHROME000000.rap. If it is renamed the console cannot find it, so give it exactly as you got it.
Save dataAt most one.zipThe saved games the console starts with. This is the zip that Emulator > Export Save Data... writes, given back unchanged. It holds the user's savedata folder, with one directory per save (BLUS30007-SAVE-..., with PARAM.SFO, icons and the game's own files). It is unpacked onto the console's hard disk before the machine starts, so a run can continue where another stopped. The file is never changed. The project and the movie record exactly which file it was, so a movie that starts from a saved game can be played back by anyone who has the same file. Leave it empty and the console has no saves. A zip that holds anything else is refused.

Controls in each group

  • Add opens a file picker titled Add to and the group name. It starts in the ROM folder set under Config, Paths. It filters to the group's file types, and you can switch it to All files. You can select several files at once.
  • Remove takes the selected row out of the list. It does not delete the file on disk.
  • Up and Down arrows appear in the groups that take more than one file, which are Packages and Licences. They move the selected row. The order is kept in the project.
  • Drag and drop works on each list. A file you drop lands in the group you drop it on. Folders are ignored.

Rules

  • Groups whose How many is Exactly one or At least one need a file. These are Game. Next will not continue until each has a file.
  • Each group's title shows how many files it takes and the file types it expects. A file with another extension is still added, and a message at the bottom tells you it is not what the group expects.
  • Adding a file with the same name as one already in the group does nothing.
  • A group is greyed out when its condition is not met. The description of the group starts with that condition in italics.

Starting from a dropped file

If you drag a file onto the main Chimera window, the wizard opens with the core that claims the file's extension already chosen. The file goes into the first group that lists that extension. RPCS3 claims .bin, .elf, .iso, .pkg, .self, .zip.

Page 3 Set up the machine

This page asks for the emulation settings. Every setting here shapes the emulated machine, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

Settings

The grid lists the settings alphabetically. Click a row to read its description in the pane under the grid. A value that differs from the default is shown in bold. Right-click a row and choose Reset to put the default back. True or False settings and settings with a fixed set of choices are picked from a list. Number and text settings are typed in. The System and Renderer are not in the grid because Page 1 already asked for them. RPCS3 has 49 settings in the grid. All of them are always shown.

When you arrive on this page, Chimera asks the core to look up your game. If the core knows it, Chimera applies the RPCS3 wiki's recommended settings for the game and shows a note above the grid with where they came from, or that the game is not known. The note also lists the settings it changed. The core can also add settings that exist only for your game.

Page 4 Provide firmware

This page asks where to find the firmware files your choices need. It only appears when at least one setting calls for a file. With some settings it is skipped, and the page before it ends with Create instead of Next. The list changes when you go back and change a setting.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Next stays greyed out until every row that is not optional has a file.

Which files can be asked for

RPCS3 can ask for up to 1 file. Only the rows your choices call for appear. A description that starts with an italic condition is only asked for in that case.

FirmwareExpected fileSHA1What it is
PlayStation 3 System SoftwarePS3UPDAT.PUP(your own file)Asked for when the file under Game ends in .iso or the file under Game ends in .pkg.
Sony's PS3 system software update, PS3UPDAT.PUP, the file Sony distributes for the console (version 4.80 or newer). The machine decrypts it into its internal storage when it starts, before the first frame, which is how a console holds its system software. The system libraries that games use come from it. Homebrew that uses only the system's basic calls starts without it. Every real game needs it, whether it is on a disc or sold only as a download. Two projects with different versions are different machines and cannot share movies.

Page 5 Compile the game's code

This page appears when you added a game. RPCS3 translates the console's code into your computer's before running it. Doing it once now, in parallel, makes the game fast enough to work on. Otherwise every session pays for it again. It can take several minutes. The result depends only on the game and this core, so it is the same on every computer and is not part of the run.

Buttons

  • Compile starts the work. A progress bar and a status line under the list show how far it has got, and the rows change to Compiled one at a time.
  • Create stays greyed out until every module says Compiled. If you press it early, the message says to compile first. If you close the wizard during a compile, it stops the work first.

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard goes back to Page 2 and says why. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
