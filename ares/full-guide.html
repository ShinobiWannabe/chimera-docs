Before you begin

  • A core is the package that holds an emulator. This page uses the ares core, which runs 30 systems, listed under System choices on Page 1. You get it from the Releases page of the chimera-core-ares repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A savestate is a copy of the whole machine at one moment. You can return to it later.
  • A frame is one picture the game draws. A game draws many of them each second.

Page 1 Choose the core

The first page asks you to pick a core, either an emulator or a game. Everything on the later pages depends on this choice.

OptionWhat it does
KindEmulator or Game. It decides which cores the Core list shows. ares is an emulator. The wizard opens on the kind you used last, when you have cores of that kind installed.
CoreLists the installed cores of that kind. Each line shows the core name, its version date and the systems it runs. Choose the ares line. If you have two builds of one core installed, the line also shows the first eight characters of the package's fingerprint in square brackets.
SystemNames the machine to run. ares offers 30 choices, listed below. The choice decides which settings, files and firmware the later pages show.
RendererChooses how the picture is drawn, for cores that offer a choice. ares draws one way, so the box is greyed out and shows Software (Native).

Page 2 Add your files

This page asks for the game files and other data. The core decides what appears here. ares shows 3 groups of files. Hover over a group to see the core's own help text. The file types offered in each group narrow to the System you chose on Page 1.

GroupHow manyFile typesWhat it is for
Cartridge, disc or tapeAt most one.n64, .v64, .z64, .ndd, .d64, .n64dd, .fc, .nes, .unf, .unif, .md, .gen, .smd, .bin, .sms, .gg, .sg, .sg1000, .a26, .myvision, .gb, .gbc, .ws, .wsc, .z80, .tap, .tzx, .gba, .cv, .col, .msx, .rom, .cas, .wav, .tsx, .cue, .exe, .ps-exe, .a52, .ngp, .ngc, .ngpc, .zip, .sfc, .smc, .swc, .fig, .32x, .msx2, .mx2, .chd, .pce, .sgxThe game the machine loads. For most machines this is a cartridge. The PlayStation takes a .cue file, the ZX Spectrum a .tzx or .tape file and the Neo Geo a .zip romset. Only the kinds that fit the chosen machine are offered. A Nintendo 64 cartridge can be in any of its three byte orders (.z64, .n64 or .v64) and the core works out which one it is. A PlayStation and an MSX can start with nothing here. The PlayStation then shows its BIOS menu and the MSX starts its BASIC. Every other machine needs a game and says so when there is none. Some machines also need their console BIOS, which is asked for on another page. The Nintendo 64 needs none.
Save dataAt most one.sav, .srm, .eep, .fla, .ramThe saved game that a cartridge with a battery starts with. This is the file that Emulator > Export Save Data... writes (EEPROM, SRAM or Flash, whichever the cartridge has). Put it here to continue a run from where another one stopped. It must be the size of the cartridge's save chip, and is in the byte order ares writes its own save files in (as Export Save Data writes it). The file is never changed. The project and the movie record exactly which file it was, so a movie that starts from a saved game can be played back by anyone who has the same file. Only the Nintendo 64 exports and loads its saves this way so far. A Nintendo 64DD game saves on its disk instead - Export Save Data hands out the disk it wrote to, and that disk goes in the game slot of a new project. The other machines keep their saves inside the savestate. A cartridge with no save memory keeps nothing, and the project says so. Leave this empty to start with a fresh cartridge.
Cartridge in the cartridge0 to 2.bs, .st, .gb, .gbcShown when System is Super Famicom / SNES.
Some Super Famicom cartridges have a slot of their own, and this is the cartridge that goes into it. A Satellaview memory pack (.bs) goes into the BS-X cartridge. Choose the BS-X as the game above and the pack here. A Sufami Turbo minicart (.st) goes into the Sufami Turbo cartridge (a second one goes into its slot B, for the games that link two), and a Game Boy cartridge goes into a Super Game Boy. The core finds the right slot from the file itself. Leave this empty for an ordinary cartridge, which is almost every game. A game that has no such slot reports an error when a file is given here.

Controls in each group

  • Add opens a file picker titled Add to and the group name. It starts in the ROM folder set under Config, Paths. It filters to the group's file types, and you can switch it to All files. You can select several files at once.
  • Remove takes the selected row out of the list. It does not delete the file on disk.
  • Up and Down arrows appear in the groups that take more than one file, which are Cartridge in the cartridge. They move the selected row. The order is kept in the project.
  • Drag and drop works on each list. A file you drop lands in the group you drop it on. Folders are ignored.

Rules

  • No group must be filled. Some systems start with nothing added, and others report that a game is missing when you press Create.
  • Each group's title shows how many files it takes and the file types it expects. A file with another extension is still added, and a message at the bottom tells you it is not what the group expects.
  • Adding a file with the same name as one already in the group does nothing.
  • A .cue file (a small text file that lists a disc's track files) counts as one row and shows how many track files it brings. All its track files must sit in the same folder as the .cue file, or the wizard refuses it and names the missing file.
  • A group is greyed out when its condition is not met. The description of the group starts with that condition in italics.

Starting from a dropped file

If you drag a file onto the main Chimera window, the wizard opens with the core that claims the file's extension already chosen. The file goes into the first group that lists that extension. ares claims 53 extensions. The File types column above shows them.

Page 3 Set up the machine

This page asks for the emulation settings. Every setting here shapes the emulated machine, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

Settings

The grid lists the settings alphabetically. Click a row to read its description in the pane under the grid. A value that differs from the default is shown in bold. Right-click a row and choose Reset to put the default back. True or False settings and settings with a fixed set of choices are picked from a list. Number and text settings are typed in. The System and Renderer are not in the grid because Page 1 already asked for them. ares has 56 settings in the grid. 56 of them only appear in some cases. Page 4 Provide firmware

This page asks where to find the firmware files your choices need. It only appears when at least one setting calls for a file. With some settings it is skipped, and the page before it ends with Create instead of Next. The list changes when you go back and change a setting or the System.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Create stays greyed out until every row that is not optional has a file.

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard goes back to Page 2 and says why. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

Some cores add a page that compiles the game's code before the project is made. ares does not, so you will not see it.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
