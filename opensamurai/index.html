OpenSamurai

Quickstart

System Sword of the Samurai

Quickstart

  1. Put the OpenSamurai core file (it ends in .chimeraCore) in the Cores folder next to Chimera.exe.
  2. Open the File menu and choose New Chimera Project.
  3. Page 1. Choose OpenSamurai in the Core list, then press Next.
  4. Page 2. Press Add under the group that fits your game and pick your file. Some systems can also start with nothing added. Press Next.
  5. Page 3. Change settings if you want to. The defaults work for most games. Press Next, or Create if that is what the button says.
  6. Page 4. Give each file in the list, then press Create. The files come from hardware or game copies you own.
  7. Chimera opens the new project in TAStudio (its input editor) at the first frame.

You can also drag a game file onto the Chimera window. The wizard then opens with the core and the file already chosen.

Before you begin

  • A core is the package that holds an emulator. This page uses the OpenSamurai core, which runs Sword of the Samurai. You get it from the Releases page of the chimera-core-opensamurai repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A hash is a fingerprint of a file's contents, like a SHA1.
  • A frame is one picture the game draws. A game draws many of them each second.

Buttons on every page

ButtonWhat it does
BackReturns to the page before. It is greyed out on Page 1. Pages that do not apply are skipped. Your answers are kept.
NextGoes to the next page. On the last page it is called Create. If something is missing, a red message at the bottom left says what.

Page 1 Choose the core

The first page asks you to pick a core, either an emulator or a game. Everything on the later pages depends on this choice.

OptionWhat it does
KindEmulator or Game. It decides which cores the Core list shows. OpenSamurai is a game core, which runs one game. The wizard opens on the kind you used last, when you have cores of that kind installed.
CoreLists the installed cores of that kind. Each line shows the core name, its version date and the systems it runs. Choose the OpenSamurai line. If you have two builds of one core installed, the line also shows the first eight characters of the package's fingerprint in square brackets.
SystemNames the machine to emulate. OpenSamurai has one, Sword of the Samurai, so the box is greyed out.
RendererChooses how the picture is drawn, for cores that offer a choice. OpenSamurai draws one way, so the box is greyed out and shows Software (Native).

A link at the bottom takes you to the Chimera issue page, for reporting problems and asking for features. If no core is installed, Next shows a message asking you to pick one.

Page 2 Add your files

This page asks for the game files and other data. The core decides what appears here. OpenSamurai shows 1 group of files. Hover over a group to see the core's own help text.

GroupHow manyFile typesWhat it is for
Saved gameAt most one.datA TALLTALE.DAT file, the game's own saved game. The game writes one when Alt+S is pressed at the Home Option scroll, and 'Restore Saved Game' in the career choices loads it. The game keeps its own saves in the machine's memory and never changes this file.

Controls in each group

  • Add opens a file picker titled Add to and the group name. It starts in the ROM folder set under Config, Paths. It filters to the group's file types, and you can switch it to All files. You can select several files at once.
  • Remove takes the selected row out of the list. It does not delete the file on disk.
  • Drag and drop works on each list. A file you drop lands in the group you drop it on. Folders are ignored.

Rules

  • No group must be filled. Some systems start with nothing added, and others report that a game is missing when you press Create.
  • Each group's title shows how many files it takes and the file types it expects. A file with another extension is still added, and a message at the bottom tells you it is not what the group expects.
  • Adding a file with the same name as one already in the group does nothing.

Page 3 Set up the game

This page asks for the emulation settings. Every setting here shapes the emulated game, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

Settings

The grid lists the settings alphabetically. Click a row to read its description in the pane under the grid. A value that differs from the default is shown in bold. Right-click a row and choose Reset to put the default back. True or False settings and settings with a fixed set of choices are picked from a list. Number and text settings are typed in. The System and Renderer are not in the grid because Page 1 already asked for them. OpenSamurai has 5 settings in the grid. All of them are always shown.

SettingAllowed valuesDefaultWhat it does
Random Seedany text0The starting number for all of the game's random numbers - the crest question, the characters, the encounters, and the opponents in duels, melees and battles. The DOS programs took their random numbers from the clock. OpenSamurai takes all of them from this one number. It can be any 64-bit number, in decimal or in hexadecimal after 0x, in the same form OpenSamurai's own program takes it (OPENSAMURAI_SEED). A number that program printed gives the same random numbers here. A movie records the number it ran with.
Releasefloppy, downloadfloppyWhich release of Sword of the Samurai 445.03 the project's files come from - the original floppy (the one the published speedrun uses) or the download sold on Steam and GOG.com. Both are the same game. Only START.EXE (whose code OpenSamurai does not run) and the AdLib driver differ.
Skip the TitleTrue or FalseFalseStarts the game with its /NT option. The title sequence is left out and the game starts at the copy-protection question.
Soundroland, adlib, speaker, tandy, nonerolandThe sound device the game is set up for - the Roland MT-32 (the default), the AdLib, the IBM PC speaker, the Tandy, or none. The AdLib needs the download's ASOUND.SAM, because OpenSamurai's AdLib sound is built from it and the floppy has an older driver. The Roland needs RSOUND.SAM and the two ROMs of an MT-32 (version 1.07, the first generation, which the game was made for). The project supplies them as firmware. With the PC speaker the title sequence runs slower, as it did originally.
Start Date and Timeany text1989-10-25 12.00.00The PC's date and time when the game starts, written as YYYY-MM-DD HH - MM - SS. The clock then advances with the frames. The game reads it as the time, for example for how long a prompt waits and when an encounter on the road can happen. A movie records the start time it ran with.

Page 4 Provide firmware

This page asks where to find the firmware and game data files the core needs. OpenSamurai always asks for at least one, so this page always appears. The list changes when you go back and change a setting.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Create stays greyed out until every row that is not optional has a file.

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard goes back to Page 2 and says why. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

Some cores add a page that compiles the game's code before the project is made. OpenSamurai does not, so you will not see it.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
