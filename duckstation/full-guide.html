DuckStation

Full Guide

Systems PlayStation · Namco System 11 · Konami GQ

Before you begin

  • A core is the package that holds an emulator. This page uses the DuckStation core, which runs PlayStation, Namco System 11, Konami GQ. You get it from the Releases page of the chimera-core-duckstation repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A savestate is a copy of the whole machine at one moment. You can return to it later.
  • A hash is a fingerprint of a file's contents, like a SHA1.
  • A frame is one picture the game draws. A game draws many of them each second.

Buttons on every page

ButtonWhat it does
BackReturns to the page before. It is greyed out on Page 1. Pages that do not apply are skipped. Your answers are kept.

Page 1 Choose the core

The first page asks you to pick a core, either an emulator or a game. Everything on the later pages depends on this choice.

OptionWhat it does
KindEmulator or Game. It decides which cores the Core list shows. DuckStation is an emulator. The wizard opens on the kind you used last, when you have cores of that kind installed.
CoreLists the installed cores of that kind. Each line shows the core name, its version date and the systems it runs. Choose the DuckStation line. If you have two builds of one core installed, the line also shows the first eight characters of the package's fingerprint in square brackets.
SystemNames the machine to run. DuckStation offers 3 choices, listed below. The choice decides which settings, files and firmware the later pages show.
RendererChooses how the picture is drawn. The choices are Software (Native), Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan). The default is Software (Native). A Hardware choice uses your graphics card. It is fast, but the picture is drawn outside the savestate, so video can differ on another computer. A warning appears under the box when you pick one.

Page 2 Add your files

This page asks for the game files and other data. The core decides what appears here. DuckStation shows 4 groups of files. Hover over a group to see the core's own help text. The file types offered in each group narrow to the System you chose on Page 1.

GroupHow manyFile typesWhat it is for
Discs or program0 to 8.cue, .chd, .bin, .img, .iso, .pbp, .ecm, .exe, .psexe, .ps-exeShown when System is PlayStation.
What the console runs. This is usually a CD image - a .cue file with the .bin files it names beside it, a .chd, a single .bin, .img or .iso of one data track, a PlayStation Store .pbp, or an .ecm. For a game on several discs, list them all in order. The first is in the drive when the console is switched on, and the Next Disc, Previous Disc and Disc Swap controls change it when the game asks. It can also be one PlayStation EXECUTABLE (.exe, .psexe, .ps-exe), which is how homebrew and test programs are distributed. The tray then stays empty, and the console is given the program once its own ROM has started. With nothing here the console starts into its own menu.
Memory cards0 to 2.mcdShown when System is PlayStation.
Memory cards the console starts with, for a project that begins from a saved game. A card is a raw image of 131072 bytes named for its slot - memcard1.mcd for slot 1 and memcard2.mcd for slot 2. A .mcr or .mc file from another emulator is the same kind of file under another name, so rename it. Emulator > Export Save Data writes the cards back out under the same names. A card with any other name is refused and not silently ignored.
Rom set1 to 3.zip, .chdShown when System is one of Namco System 11, Konami GQ.
The game's MAME rom set. This is the .zip, named exactly as MAME names it (tekken.zip, cryptklr.zip). The set is recognised by its name, so a renamed zip is an unknown game. It must be a complete (non-merged) set from a current MAME release - every rom the game needs, under the name MAME gives it now, including the roms a clone shares with its parent. A game with a hard disk or a CD has it as a .chd, named as MAME names it (420uaa04.chd). Put it here beside the zip. Where the board's own firmware is a separate zip, it comes from the firmware list and not from here.
Board memory0 to 4.nvShown when System is one of Namco System 11, Konami GQ.
What the board keeps while the power is off - the EEPROM with the operator's settings and the high scores, or a flash card. It is optional. Without it the board starts blank, as a new board did, and may spend its first start setting it up. The files are the ones Export Save Data writes, and they are read by name (at28c16.nv, eeprom.nv). The board says which files it keeps, and a file with another name is refused.

Controls in each group

  • Add opens a file picker titled Add to and the group name. It starts in the ROM folder set under Config, Paths. It filters to the group's file types, and you can switch it to All files. You can select several files at once.
  • Remove takes the selected row out of the list. It does not delete the file on disk.
  • Up and Down arrows appear in the groups that take more than one file, which are Discs or program, Memory cards, Rom set and Board memory. They move the selected row. The order is kept in the project.
  • Drag and drop works on each list. A file you drop lands in the group you drop it on. Folders are ignored.

Rules

  • Groups whose How many is Exactly one or At least one need a file. These are Rom set. Next will not continue until each has a file.
  • Each group's title shows how many files it takes and the file types it expects. A file with another extension is still added, and a message at the bottom tells you it is not what the group expects.
  • Adding a file with the same name as one already in the group does nothing.
  • A .cue file (a small text file that lists a disc's track files) counts as one row and shows how many track files it brings. All its track files must sit in the same folder as the .cue file, or the wizard refuses it and names the missing file.
  • A group is greyed out when its condition is not met. The description of the group starts with that condition in italics.

Starting from a dropped file

If you drag a file onto the main Chimera window, the wizard opens with the core that claims the file's extension already chosen. The file goes into the first group that lists that extension. DuckStation claims .chd, .cue, .ecm, .exe, .pbp, .ps-exe, .psexe.

Page 3 Set up the machine

This page asks for the emulation settings. Every setting here shapes the emulated machine, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

Settings

The grid lists the settings alphabetically. Click a row to read its description in the pane under the grid. A value that differs from the default is shown in bold. Right-click a row and choose Reset to put the default back. True or False settings and settings with a fixed set of choices are picked from a list. Number and text settings are typed in. The System and Renderer are not in the grid because Page 1 already asked for them. DuckStation has 30 settings in the grid. 27 of them only appear in some cases. Each of those descriptions starts with the case in italics.

SettingAllowed valuesDefaultWhat it does
BIOSv1.0-j, v1.1-j, v2.0-a, v2.0-e, v2.1-a, v2.1-e, v2.1-j, v2.2-a, v2.2-e, v2.2-j, v3.0-a, v3.0-e, v3.0-j, v4.0-j, v4.1-a, v4.1-e, v4.3-j, v4.4-e, v4.5-a, v4.5-ev4.1-aShown when System is PlayStation.
Which of Sony's boot ROMs the console has. The boot ROM is the machine's operating system. It differs by region and by revision. For example 'v4.1-a' is version 4.1 for North America (the one in the SCPH-7001), a 'j' is for Japan and an 'e' is for Europe. A project records one of them, and Chimera asks for that file. A game runs on any BIOS that accepts its disc, but a movie plays back only on the one it was made with.
Console Regionauto, ntsc-u, ntsc-j, palautoShown when System is PlayStation.
Which market the console was made for. It decides the video timing (NTSC 59.83 Hz or PAL 49.76 Hz) and which discs the drive accepts. 'auto' reads the disc and becomes the console that disc was made for, which is right for almost every game. With no disc it becomes the console its BIOS was made for.
Controller 1none, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousedualshockShown when System is PlayStation.
What is plugged into port 1. 'dualshock' is the analog controller, in the mode it starts in when switched on. 'digital' is the original pad with no sticks. 'analogJoystick' is the flight controller with two sticks. 'negcon' is Namco's twisting pad for racing games, and 'negconRumble' is the later one with motors. 'guncon' and 'justifier' are the two light guns. They are not interchangeable, and a game works with one or the other. 'mouse' is the PlayStation Mouse. DuckStation's game database lists games that cannot work with a DualShock. Such a game gets the digital pad whatever is chosen here.
Controller 1Bnone, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousenoneShown when System is PlayStation.
What is plugged into socket B of the multitap in port 1 (P3 in a movie). It is empty unless that multitap is plugged in.
Controller 1Cnone, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousenoneShown when System is PlayStation.
What is plugged into socket C of the multitap in port 1 (P4 in a movie). It is empty unless that multitap is plugged in.
Controller 1Dnone, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousenoneShown when System is PlayStation.
What is plugged into socket D of the multitap in port 1 (P5 in a movie). It is empty unless that multitap is plugged in.
Controller 2none, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousenoneShown when System is PlayStation.
What is plugged into port 2. By default nothing is, because a game can see any controller that is plugged in. 'dualshock' is the analog controller, in the mode it starts in when switched on. 'digital' is the original pad with no sticks. 'analogJoystick' is the flight controller with two sticks. 'negcon' is Namco's twisting pad for racing games, and 'negconRumble' is the later one with motors. 'guncon' and 'justifier' are the two light guns. They are not interchangeable, and a game works with one or the other. 'mouse' is the PlayStation Mouse. DuckStation's game database lists games that cannot work with a DualShock. Such a game gets the digital pad whatever is chosen here.
Controller 2Bnone, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousenoneShown when System is PlayStation.
What is plugged into socket B of the multitap in port 2 (P6 in a movie). It is empty unless that multitap is plugged in.
Controller 2Cnone, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousenoneShown when System is PlayStation.
What is plugged into socket C of the multitap in port 2 (P7 in a movie). It is empty unless that multitap is plugged in.
Controller 2Dnone, digital, dualshock, analogJoystick, negcon, negconRumble, guncon, justifier, mousenoneShown when System is PlayStation.
What is plugged into socket D of the multitap in port 2 (P8 in a movie). It is empty unless that multitap is plugged in.
Cropoverscan, none, bordersoverscanHow much of the console's picture is handed to Chimera. 'overscan' cuts off what the edge of a television hid. 'none' keeps the whole picture, black edges included. 'borders' cuts to the area the game placed its picture in. It changes the picture only.
Downsamplingdisabled, box, adaptivedisabledShown when Renderer is one of Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan).
Draws at the Internal Resolution and then shrinks the picture that is handed to Chimera. 'box' averages everything back to the console's resolution. 'adaptive' keeps 3D sharp and smooths only 2D. 'disabled' hands over every pixel that was drawn.
Interlaced Modesweave, progressiveweaveWhat happens in the console's interlaced video modes (480 lines, used by most menus and by many games). 'weave' is what the console does. On each frame it draws and shows one field, which is every other line, and the frame handed to Chimera is that field combined with the previous one, as a television showed it. 'progressive' is DuckStation's own default and an improvement - every line is drawn on every frame. The picture is steadier, but it is a different machine, because video memory no longer holds what a PlayStation would have put there.
Internal Resolution1x, 2x, 3x, 4x, 5x, 6x, 7x, 8x1xShown when Renderer is one of Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan).
How many pixels the hardware renderer draws for each pixel of the console. At 2x a 320x240 game is drawn at 640x480, and at 8x at 2560x1920. Polygons become sharper, and 2D art stays the size it was made at. It does nothing with the software renderer. A game that reads its picture back gets it scaled down again, and that is not always exactly what it drew. So it is part of the machine, and a movie needs the same value.
Log the MachineTrue or FalseFalseWrites DuckStation's own log, and the messages it would have shown on screen, to the core's output. It does not change the machine.
Memory Card 1True or FalseTrueShown when System is PlayStation.
Puts a memory card in slot 1. The card is kept in the console's memory. It is part of every savestate and goes back in time together with the game that wrote to it. Nothing is written to your disk until you ask for it with Emulator > Export Save Data, which gives you memcard1.mcd. To start from a card you already have, put it in the project's Save Data under that name.
Memory Card 2True or FalseFalseShown when System is PlayStation.
Puts a memory card in slot 2. It works the same way as Memory Card 1, and its file is memcard2.mcd.
Multitapnone, port1, port2, bothnoneShown when System is PlayStation.
A multitap turns one controller port into four sockets, for games of up to five players (one multitap) or eight (two). 'port1' puts a multitap in port 1. Controller 1 is then its socket A, and Controllers 1B, 1C and 1D are its other three sockets. A game that was not written for the multitap may not see ANY controller through it, so leave it out unless the game asks for one. It is part of the machine, so a movie needs the same value.
PGXP Geometry CorrectionTrue or FalseFalseShown when Renderer is one of Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan).
Keeps the corners of polygons at the precision the game calculated, instead of rounding them to whole pixels as the console did. This is what stops 3D models from wobbling. It does not change the picture only. The precise corners also decide which polygons are thrown away, and how long the console's graphics chip is busy depends on what it drew. So a game runs slightly differently with it, and a movie made with PGXP does not play back without it.
PGXP - CPU ModeTrue or FalseFalseShown when PGXP Geometry Correction is True.
Tracks precise values through every processor instruction, and not only through the geometry chip. A few games need it. It is much slower.
PGXP - Culling CorrectionTrue or FalseTrueShown when PGXP Geometry Correction is True.
Also uses the precise corners to decide which polygons face away. This closes the hairline gaps that precise corners otherwise open.
PGXP - Depth BufferTrue or FalseFalseShown when PGXP Geometry Correction is True.
Gives polygons a depth test, which the console did not have, to stop them poking through each other. It breaks games that draw in an order of their own. The depth of a frame is not kept in a savestate. After a load it starts empty, as it does on every frame where the game clears it.
PGXP - Perspective Correct ColoursTrue or FalseFalseShown when PGXP Geometry Correction is True.
The same for shading. The difference is usually small, and it is wrong in a few games.
PGXP - Perspective Correct TexturesTrue or FalseTrueShown when PGXP Geometry Correction is True.
Uses the depth that PGXP recovers to map textures in perspective. This straightens the warped textures that the console's simpler mapping gives large polygons.
Scale DitheringTrue or FalseTrueShown when Renderer is one of Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan).
Makes the dither pattern as fine as the picture, instead of the console's pattern enlarged. It applies when True Colour is off and Internal Resolution is above 1x. It has no effect at 1x.
Skip the Console BootTrue or FalseFalseShown when System is PlayStation.
Starts the game without the console's own logos. The ROM is patched to jump past them, so the machine reaches the game in a different state from one that started in full. A movie made one way does not play back the other way.
Sprite Texture Filteringnearest, bilinear, bilinearBinAlpha, jinc2, jinc2BinAlpha, xbr, xbrBinAlphanearestShown when Renderer is one of Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan).
The same choice for 2D sprites and backgrounds. These usually look better as the artist drew them.
Texture Filteringnearest, bilinear, bilinearBinAlpha, jinc2, jinc2BinAlpha, xbr, xbrBinAlphanearestShown when Renderer is one of Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan).
How the textures on 3D polygons are sampled. 'nearest' is what the console does - each texture pixel is a square. 'bilinear' blends neighbouring pixels. 'jinc2' and 'xbr' are sharper and slower. The 'BinAlpha' choices keep the edges of transparent areas hard, which avoids the halos that filtering otherwise draws around cut-out textures.
True ColourTrue or FalseFalseShown when Renderer is one of Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan).
Draws in 24-bit colour instead of the console's 15-bit colour with dithering. Gradients lose their bands and their dither pattern. DuckStation turns this on by default. Here the console's own colour depth is the default, and this setting is the improvement. A game that reads its picture back gets it reduced to 15-bit again.
Widescreen Hackoff, 16 to 9, 19 to 9, 20 to 9offShown when System is PlayStation.
DuckStation's widescreen hack. The game's 3D view is widened to suit a screen of this shape, by changing what its geometry processor calculates. The picture is still the console's own, squeezed. Set Config > Display > Aspect Ratio to the same shape to see it as intended. The 2D parts of a game (menus, status displays, sprites) are not widened and look stretched. It changes the MACHINE and not only the picture - different geometry is drawn, and that takes the video chip a different time. So a movie made with it needs it. DuckStation's game database lists games that break with it, and for those it is turned off.

Page 4 Provide firmware

This page asks where to find the firmware files your choices need. It only appears when at least one setting calls for a file. With some settings it is skipped, and the page before it ends with Create instead of Next. The list changes when you go back and change a setting or the System.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Create stays greyed out until every row that is not optional has a file.

Namco C76 sound processornamcoc76.zip(your own file)Asked for when System is Namco System 11.
The program inside the sound processor that every Namco System 11 board has (the C76, a Mitsubishi M37702). The file is namcoc76.zip as MAME names it, with c76.bin inside. It is a MAME set and is used whole. The core reads the rom out of it and checks that rom by its own CRC and SHA-1. No size or hash of the zip itself is required, because zips of the same rom differ.

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard goes back to Page 2 and says why. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

Some cores add a page that compiles the game's code before the project is made. DuckStation does not, so you will not see it.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
