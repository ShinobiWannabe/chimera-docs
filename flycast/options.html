Flycast

Options

Settings the Flycast core exposes in the New Project wizard. Click a column heading to sort. Click again to reverse. Settings that are identical on every machine are listed once.

Settings

18 of 18
Machinedreamcast, naomi, naomi2, atomiswavedreamcastWhich of Flycast's machines this project is. 'dreamcast' is the console. 'naomi' is Sega's arcade board built from the same parts, for both cartridge and GD-ROM games. 'naomi2' is its successor with two graphics chips, and 'atomiswave' is Sammy's board. The three arcade machines take a MAME ROM set (the zip, with the name MAME gives it, because the name is how the set is recognised). Their BIOS comes from the firmware page: naomi.zip, naomi2.zip or awbios.zip. A set for another board is refused with a message that says which board it needs. The machine decides the inputs, the files and the firmware of the project, and a movie made on one machine does not run on another.
CPUjit, interpreterjitHow the console's SH4 processor is emulated. The two choices give slightly different machines, so this is part of the machine a movie was made on and not just a speed setting. 'jit' translates the game's code into your computer's own code. It is about four times faster, and it is what Flycast itself uses on every desktop computer, so it is the Dreamcast most people have seen. 'interpreter' runs the code one instruction at a time. It is slower and simpler to reason about when a game misbehaves. The two keep the same clock but count time differently (per instruction or per block of code), so interrupts happen at different moments and a movie recorded with one does not play back with the other. 'jit' is the default since 2026-09-22. A project made before that date that never set this value gets a different machine now, and its movie will not play back. Set the value explicitly for anything already recorded.
Controller 1 Typenone, gamepad, arcadeStick, twinStick, xl, mouse, lightGungamepadWhat is plugged into port 1. 'gamepad' is the standard Dreamcast controller. 'arcadeStick' is the arcade stick, which has the same buttons and nothing analog. 'twinStick' is the pair of sticks made for Virtual On. It reports a second direction pad (P1 Up2 to Right2) and nothing analog. 'xl' is the PantherDC controller, which reports everything: the C, D and Z buttons, both direction pads and a second analog stick. 'mouse' and 'lightGun' are different kinds of device with their own axes. The mouse reports movement and the gun reports a position on the screen. The device in a port is part of the machine. A game asks what is connected and behaves accordingly, so two projects that differ here cannot share movies. A memory card goes into the first expansion slot of every device that has one: the controllers, the sticks and the light gun. A mouse has none.

Boot ROMhle, realhleWhich BIOS the machine runs. 'hle' is Flycast's own replacement. It starts most discs and needs no files. It is not the BIOS Sega shipped, so anything the real BIOS shows (the start-up animation, the settings screens) is only correct with the real one. 'real' asks the project for dc_boot.bin and dc_flash.bin. The two are DIFFERENT MACHINES and cannot share movies.
Power-on Clock0 to 21474836470The date and time the machine has when it starts, counted in seconds from the Dreamcast's own starting date (1 January 1950). A Dreamcast has a battery-backed clock and writes the time into memory when it starts, where the BIOS and games read it. If the machine used your computer's clock it would be different on every run, and a movie would not play back. With this fixed value every run starts the same, and a movie records the value it ran with. The value also decides the console's ID, which some games read.
Regionjapan, usa, europeusaWhich region the machine is. On a Dreamcast the region is stored in the console's flash memory. A game may check it and refuse to run, or use it to choose a language. On the arcade boards it chooses which of the BIOS ROMs in the set is used: Japan, USA or Export (called 'europe' here). The game follows the BIOS in its language, in some content, and in whether it starts at all, because a few sets exist for one region only. When the set has no BIOS for the chosen region, the core uses the one it has and says so in the log.
System Languagejapanese, english, german, french, spanish, italianenglishThe language in the machine's own settings. Games read it to choose their text.
Television Standardntsc, pal, palM, palNntscWhich television standard the machine is set up for. It changes the frame rate and the number of picture lines, so it is part of the machine and not a display preference.
Renderersoftware, opengl, opengl-hw, vulkan-hwsoftwareWhich renderer draws the picture. 'software' is Flycast's reference software renderer and the default. It runs completely inside the sandbox, so the picture is the same on every computer. It is about half as fast as a graphics card (Re-Volt, 1500 frames with every frame drawn, takes 28 s on a Ryzen against 15 s on a GTX 1060). 'opengl' is Flycast's own OpenGL renderer, the one Flycast is tested with and most games are known to look right in. Here it draws with a software OpenGL built into the core, which is slower than 'software'. It is also inside the sandbox and gives the same picture everywhere, and a movie made with either of these two plays back with the other. 'opengl-hw' is the same Flycast renderer drawing on your computer's graphics card, outside the sandbox. It is much faster, and the picture is NOT guaranteed to be the same on every computer, because it comes from your graphics driver. It needs a Chimera built with the GPU bridge. Without one it draws with the software OpenGL. 'vulkan-hw' is Flycast's Vulkan renderer drawing on your graphics card. What is said of 'opengl-hw' is true of it: the picture comes from your graphics driver. It has nothing to fall back on: it needs a graphics driver that has Vulkan and a Chimera that hands Vulkan to cores, and without either the project does not start and says why.
Internal Resolution1x, 2x, 3x1xHow large the renderer draws each frame. A Dreamcast draws 640x480. '2x' and '3x' draw the same frame at 1280x960 and 1920x1440, so edges are smoother and a recording has real detail. It costs drawing time and nothing else. ONLY the OpenGL and Vulkan renderers can do it. The 'software' renderer always draws 640x480 and ignores this setting. It is not part of the machine. Flycast draws a frame larger only when it goes to the screen. A picture that the game will read back is drawn at 640x480 whatever this setting is, and the dozen or so games known to read their own picture (Silent Scope, Cosmic Smash, Densha de Go! 2 and others) are handled automatically. This core's tests check it: the same program at 1x and at 3x leaves the system memory, video memory, sound memory and flash memory identical byte for byte, and only the picture differs.
Texture Filteringmachine, nearest, linearmachineHow a texture is drawn when it is stretched or shrunk. 'machine' does what the game asked for, texture by texture, and gives the picture the Dreamcast drew. 'nearest' always uses the nearest texture pixel. Pixel art and text stay sharp, which is usually wanted for a video, and a texture stretched large looks blocky. 'linear' always blends, which smooths a game that asked for nearest. Only the OpenGL and Vulkan renderers have this choice. The 'software' renderer draws as the Dreamcast's graphics chip does and ignores it. The setting changes the picture only, with one exception. For the few games whose pictures are copied back into video memory (Flycast turns that on for them by name), the game reads the pixels this setting changes, so for those games it is part of the machine.
Transparent SortingperTriangle, perStrip, perPixelperTriangleHow see-through polygons are put in order before they are blended. The Dreamcast's graphics chip orders them for each pixel. 'perPixel' does the same in the 'software' renderer. It is what a game needs when overlapping see-through parts appear in the wrong order (for example Sonic Shuffle), and it costs time in scenes with many layers. The OpenGL renderers cannot do it here, because it needs OpenGL 4.3 and the OpenGL built into this core is version 3.3. With 'opengl' and 'opengl-hw', 'perPixel' orders triangle by triangle. 'perTriangle' (Flycast's default) and 'perStrip' (cheaper, and right for a few games) are Flycast's other orders, and the 'software' renderer can use them too. This changes the picture only, except in a game that copies its picture back into video memory.
NAOMI Bios Boardnaomi, hod2bios, f355bios, f355dlx, airlbiosnaomiWhich BIOS set the arcade cabinet has. This is the MAME set the firmware page asks for. 'naomi' (naomi.zip) is right for nearly every game. A few games came in their own cabinets with their own BIOS and refuse the ordinary one. The House of the Dead 2 needs 'hod2bios'. Ferrari F355 Challenge needs 'f355dlx' (the deluxe cabinet with three screens) or 'f355bios' (the twin cabinet). Airline Pilots needs 'airlbios'. Flycast knows which BIOS each game needs, and loading a game with the wrong one gives a message that says so.
Coin SettingfreePlay, coinsfreePlayHow the cabinet charges for a game. Flycast writes this into the game's settings memory when it sets the machine up. 'freePlay' is Flycast's default and what most people have seen: Start begins a game and the Coin button is not needed. 'coins' is the board as an arcade operator received it: each Coin press gives a credit, and a game needs as many credits as its own settings ask for. It is part of the machine, so a movie made with one choice does not play back with the other.
Vertical Gamescabinet, nonecabinetWhat to do with a game made for a monitor turned on its side, such as the vertical shooting games. Flycast knows which games these are. 'cabinet' turns the picture as the cabinet did, so it is 480 wide and 640 tall and appears upright. 'none' leaves the machine's own 640x480 picture as it is, sideways. The game runs the same either way. Only the picture differs.

About this data

18 settings, 46 rows. There is one row for each machine and each option. A setting for several machines is repeated for each machine. A setting with no rule is listed under every machine as 'Always shown'. Origin says where the setting came from.
