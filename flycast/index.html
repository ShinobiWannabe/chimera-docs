Flycast

Quickstart

Systems Dreamcast · Sega NAOMI · Sega NAOMI 2 · Sammy Atomiswave

Quickstart

  1. Put the Flycast core file (it ends in .chimeraCore) in the Cores folder next to Chimera.exe.
  2. Open the File menu and choose New Chimera Project.
  3. Page 1. Choose Flycast in the Core list and pick your system in the System list, then press Next.
  4. Page 2. Press Add under Disc and Rom set and pick your game files. Press Next.
  5. Page 3. Change settings if you want to. The defaults work for most games. Press Next, or Create if that is what the button says.
  6. Page 4 only appears when your choices need firmware files. Give each file in the list, then press Create.
  7. Chimera opens the new project in TAStudio (its input editor) at the first frame.

You can also drag a game file onto the Chimera window. The wizard then opens with the core and the file already chosen.

Before you begin

  • A core is the package that holds an emulator. This page uses the Flycast core, which runs Dreamcast, Sega NAOMI, Sega NAOMI 2, Sammy Atomiswave. You get it from the Releases page of the chimera-core-flycast repository on GitHub. In Chimera, the File menu entry Core Manager lists the cores you have installed.
  • A project is what Chimera creates for one game. It records the names and SHA1 values of your files, your settings and your recorded inputs. A SHA1 is a fingerprint of a file's contents. A project never records where your files are on disk.
  • Firmware means system files copied from real hardware or from a game, such as a BIOS (the built-in startup program of a console or computer). Chimera does not include any.
  • Nothing is saved to disk when you press Create. The project stays in memory until you choose Save Project, which asks where to put it.
  • A movie is a recording of the inputs you press. It plays back the same way each time.
  • A savestate is a copy of the whole machine at one moment. You can return to it later.
  • A hash is a fingerprint of a file's contents, like a SHA1.
  • A recompiler (also called a JIT) translates the console's code into your computer's code before running it, which is fast. An interpreter reads the console's code one step at a time, which is slower.
  • A frame is one picture the game draws. A game draws many of them each second.

Page 1 Choose the core

The first page asks you to pick a core, either an emulator or a game. Everything on the later pages depends on this choice.

OptionWhat it does
KindEmulator or Game. It decides which cores the Core list shows. Flycast is an emulator. The wizard opens on the kind you used last, when you have cores of that kind installed.
CoreLists the installed cores of that kind. Each line shows the core name, its version date and the systems it runs. Choose the Flycast line. If you have two builds of one core installed, the line also shows the first eight characters of the package's fingerprint in square brackets.
SystemNames the machine to run. Flycast offers 4 choices, listed below. The choice decides which settings, files and firmware the later pages show.
RendererChooses how the picture is drawn. The choices are Software (Native), Software (OpenGL), Hardware (OpenGL), Hardware (Vulkan). The default is Software (Native). A Hardware choice uses your graphics card. It is fast, but the picture is drawn outside the savestate, so video can differ on another computer. A warning appears under the box when you pick one.

Page 2 Add your files

This page asks for the game files and other data. The core decides what appears here. Flycast shows 4 groups of files. Hover over a group to see the core's own help text. The file types offered in each group narrow to the System you chose on Page 1.

GroupHow manyFile typesWhat it is for
Disc1 to 8.gdi, .cdi, .chd, .cue, .elfShown when System is Dreamcast.
The GD-ROM image. It can be a .gdi file (with its track files next to it), a .cdi, a .chd or a .cue. A plain .elf program is also accepted, and the 'hle' BIOS starts it directly from memory, which is how homebrew is usually tested. A game on several discs takes all of them, in order. The first disc starts the machine, and the drive's inputs change discs as opening the lid does on the console. Previous Disc and Next Disc move a selection through the list and wrap around at both ends. Disc Swap opens and closes the lid, and the selected disc is in the drive when it closes. Which disc is in the drive is part of the machine, so a movie records each swap.
Rom set1 to 3.zip, .chd, .dat, .bin, .lstShown when System is one of Sega NAOMI, Sega NAOMI 2, Sammy Atomiswave.
The game's MAME ROM set. It is a zip that must have exactly the name MAME gives it (vf4.zip, ikaruga.zip), because the name is how Flycast recognises the set. A renamed zip is an unknown game. A CLONE set (another revision or region) uses its parent's set for the ROMs they share, so put the parent's zip here too, and the core works out which is which. A NAOMI GD-ROM game is its zip (the security chip) plus the disc as a .chd file with the name MAME gives it (gdl-0010.chd), also here. The BIOS set comes from the firmware page and not from here. Decrypted dumps in the old nullDC format (.dat, .bin, .lst) also load, and their own header says which board they are for.
Save data0 to 4.binShown when System is Dreamcast.
What is already saved on the machine's memory cards at the start. These are the files that Emulator > Export Save Data... writes. Put them back under the same names, vmu_A1.bin to vmu_D1.bin, one card in the first slot of each connected controller. The files are never changed. The project and the movie record exactly which files they were, so a movie that starts from a saved game can be played back by anyone who has the same files. Leave this empty and the machine starts with freshly formatted cards. File names. a memory card is identified by its file name - vmu_A1.bin to vmu_D1.bin for the first card of each connected controller, vmu_A2 to vmu_D2 for the second. These are the names Export Save Data writes. Rename the file to the card it should be.
Board memory0 to 4.eeprom, .nvmem, .binShown when System is one of Sega NAOMI, Sega NAOMI 2, Sammy Atomiswave.
What the arcade board's memory holds at the start. There are three kinds of file. <rom set>.eeprom is the settings memory of the input board (coin settings and the game's own options). <rom set>.nvmem is the BIOS's battery-backed memory (bookkeeping and backup data). vmu_B1.bin and vmu_C1.bin are the two memory cards a NAOMI control panel can hold, which a few games save to. These are the files that Emulator > Export Save Data... writes. Put back under the same names, they set the board up as it was, so a movie that starts from a cabinet configured in its test menu can be played back by anyone who has the same files. Leave this empty and the board starts as Flycast starts it - the game's default settings, empty cards, and free play or coins according to the Coin Setting. File names. the board's memory files are identified by name - <rom set>.eeprom, <rom set>.nvmem, and the cards vmu_B1.bin and vmu_C1.bin. These are the names Export Save Data writes.

Controls in each group

  • Add opens a file picker titled Add to and the group name. It starts in the ROM folder set under Config, Paths. It filters to the group's file types, and you can switch it to All files. You can select several files at once.
  • Remove takes the selected row out of the list. It does not delete the file on disk.
  • Up and Down arrows appear in the groups that take more than one file, which are Disc, Rom set, Save data and Board memory. They move the selected row. The order is kept in the project.
  • Drag and drop works on each list. A file you drop lands in the group you drop it on. Folders are ignored.

Rules

  • Groups whose How many is Exactly one or At least one need a file. These are Disc, Rom set. Next will not continue until each has a file.
  • Each group's title shows how many files it takes and the file types it expects. A file with another extension is still added, and a message at the bottom tells you it is not what the group expects.
  • Adding a file with the same name as one already in the group does nothing.
  • A .cue file (a small text file that lists a disc's track files) counts as one row and shows how many track files it brings. All its track files must sit in the same folder as the .cue file, or the wizard refuses it and names the missing file.
  • A group is greyed out when its condition is not met. The description of the group starts with that condition in italics.

Starting from a dropped file

If you drag a file onto the main Chimera window, the wizard opens with the core that claims the file's extension already chosen. The file goes into the first group that lists that extension. Flycast claims .cdi, .chd, .cue, .dat, .elf, .gdi, .lst, .zip.

Page 3 Set up the machine

This page asks for the emulation settings. Every setting here shapes the emulated machine, and the project records each one at the value you leave it on. A recording made with a project only plays back correctly with the same settings.

Settings

The grid lists the settings alphabetically. Click a row to read its description in the pane under the grid. A value that differs from the default is shown in bold. Right-click a row and choose Reset to put the default back. True or False settings and settings with a fixed set of choices are picked from a list. Number and text settings are typed in. The System and Renderer are not in the grid because Page 1 already asked for them. Flycast has 16 settings in the grid. 10 of them only appear in some cases. Each of those descriptions starts with the case in italics.

Which BIOS the machine runs. 'hle' is Flycast's own replacement. It starts most discs and needs no files. It is not the BIOS Sega shipped, so anything the real BIOS shows (the start-up animation, the settings screens) is only correct with the real one. 'real' asks the project for dc_boot.bin and dc_flash.bin. The two are DIFFERENT MACHINES and cannot share movies.

'freePlay' is Flycast's default and what most people have seen - Start begins a game and the Coin button is not needed. 'coins' is the board as an arcade operator received it - each Coin press gives a credit, and a game needs as many credits as its own settings ask for. It is part of the machine, so a movie made with one choice does not play back with the other.

CPUjit, interpreterjitHow the console's SH4 processor is emulated. The two choices give slightly different machines, so this is part of the machine a movie was made on and not just a speed setting. 'jit' translates the game's code into your computer's own code. It is about four times faster, and it is what Flycast itself uses on every desktop computer, so it is the Dreamcast most people have seen. 'interpreter' runs the code one instruction at a time. It is slower and simpler to reason about when a game misbehaves. The two keep the same clock but count time differently (per instruction or per block of code), so interrupts happen at different moments and a movie recorded with one does not play back with the other. 'jit' is the default since 2026-09-22. A project made before that date that never set this value gets a different machine now, and its movie will not play back. Set the value explicitly for anything already recorded.
Internal Resolution1x, 2x, 3x1xHow large the renderer draws each frame. A Dreamcast draws 640x480. '2x' and '3x' draw the same frame at 1280x960 and 1920x1440, so edges are smoother and a recording has real detail. It costs drawing time and nothing else. ONLY the OpenGL and Vulkan renderers can do it. The 'software' renderer always draws 640x480 and ignores this setting. It is not part of the machine. Flycast draws a frame larger only when it goes to the screen. A picture that the game will read back is drawn at 640x480 whatever this setting is, and the dozen or so games known to read their own picture (Silent Scope, Cosmic Smash, Densha de Go! 2 and others) are handled automatically. This core's tests check it - the same program at 1x and at 3x leaves the system memory, video memory, sound memory and flash memory identical byte for byte, and only the picture differs.
NAOMI Bios Boardnaomi, hod2bios, f355bios, f355dlx, airlbiosnaomiShown when System is Sega NAOMI.
Which BIOS set the arcade cabinet has. This is the MAME set the firmware page asks for. 'naomi' (naomi.zip) is right for nearly every game. A few games came in their own cabinets with their own BIOS and refuse the ordinary one. The House of the Dead 2 needs 'hod2bios'. Ferrari F355 Challenge needs 'f355dlx' (the deluxe cabinet with three screens) or 'f355bios' (the twin cabinet). Airline Pilots needs 'airlbios'. Flycast knows which BIOS each game needs, and loading a game with the wrong one gives a message that says so.
Power-on Clock0 to 21474836470The date and time the machine has when it starts, counted in seconds from the Dreamcast's own starting date (1 January 1950). A Dreamcast has a battery-backed clock and writes the time into memory when it starts, where the BIOS and games read it. If the machine used your computer's clock it would be different on every run, and a movie would not play back. With this fixed value every run starts the same, and a movie records the value it ran with. The value also decides the console's ID, which some games read.
Regionjapan, usa, europeusaWhich region the machine is. On a Dreamcast the region is stored in the console's flash memory. A game may check it and refuse to run, or use it to choose a language. On the arcade boards it chooses which of the BIOS ROMs in the set is used - Japan, USA or Export (called 'europe' here). The game follows the BIOS in its language, in some content, and in whether it starts at all, because a few sets exist for one region only. When the set has no BIOS for the chosen region, the core uses the one it has and says so in the log.
System Languagejapanese, english, german, french, spanish, italianenglishShown when System is Dreamcast.
The language in the machine's own settings. Games read it to choose their text.
Television Standardntsc, pal, palM, palNntscShown when System is Dreamcast.
Which television standard the machine is set up for. It changes the frame rate and the number of picture lines, so it is part of the machine and not a display preference.
Texture Filteringmachine, nearest, linearmachineHow a texture is drawn when it is stretched or shrunk. 'machine' does what the game asked for, texture by texture, and gives the picture the Dreamcast drew. 'nearest' always uses the nearest texture pixel. Pixel art and text stay sharp, which is usually wanted for a video, and a texture stretched large looks blocky. 'linear' always blends, which smooths a game that asked for nearest. Only the OpenGL and Vulkan renderers have this choice. The 'software' renderer draws as the Dreamcast's graphics chip does and ignores it. The setting changes the picture only, with one exception. For the few games whose pictures are copied back into video memory (Flycast turns that on for them by name), the game reads the pixels this setting changes, so for those games it is part of the machine.
Transparent SortingperTriangle, perStrip, perPixelperTriangleHow see-through polygons are put in order before they are blended. The Dreamcast's graphics chip orders them for each pixel. 'perPixel' does the same in the 'software' renderer. It is what a game needs when overlapping see-through parts appear in the wrong order (for example Sonic Shuffle), and it costs time in scenes with many layers. The OpenGL renderers cannot do it here, because it needs OpenGL 4.3 and the OpenGL built into this core is version 3.3. With 'opengl' and 'opengl-hw', 'perPixel' orders triangle by triangle. 'perTriangle' (Flycast's default) and 'perStrip' (cheaper, and right for a few games) are Flycast's other orders, and the 'software' renderer can use them too. This changes the picture only, except in a game that copies its picture back into video memory.
Vertical Gamescabinet, nonecabinetShown when System is one of Sega NAOMI, Sega NAOMI 2, Sammy Atomiswave.
What to do with a game made for a monitor turned on its side, such as the vertical shooting games. Flycast knows which games these are. 'cabinet' turns the picture as the cabinet did, so it is 480 wide and 640 tall and appears upright. 'none' leaves the machine's own 640x480 picture as it is, sideways. The game runs the same either way. Only the picture differs.

Page 4 Provide firmware

This page asks where to find the firmware files your choices need. It only appears when at least one setting calls for a file. With some settings it is skipped, and the page before it ends with Create instead of Next. The list changes when you go back and change a setting or the System.

The list

Each row shows the firmware name, the file name the core expects, its SHA1 and its status. The status reads "found" followed by a file name, "your own" followed by a file name, "not found", or "optional - core default used". A green row has a file and a red row does not. Hover over a row to read what the file is for.

Chimera looks in the Firmware folder first. That folder is set under Config, Paths and is called Firmware beside Chimera.exe by default. It also looks at files you chose for this core before. A file it finds is matched by its SHA1, so its name does not matter.

Buttons

  • Select File picks a file for the selected row. Double-clicking a row does the same. It works even when a file was already found. If the row shows a SHA1, the file must match it, or the wizard refuses the file and shows the SHA1 it found. A row that shows "(your own file)" has no fixed SHA1, so any file is accepted and its SHA1 is recorded.
  • Clear removes the file chosen for the selected row.
  • Scan Folder searches a folder you pick and fills every row it can. The folder picker has an Include sub-folders box, ticked by default. Turn it off for a very large folder. A row with a SHA1 takes only the exact file. A row with no SHA1 takes the file with the expected name. A message at the bottom says how many files were scanned and how many rows were filled.

Create stays greyed out until every row that is not optional has a file.

The Atomiswave BIOS set (awbios.zip), which holds one 64 KB ROM (bios0.ic23). It is a MAME set. The whole zip is given to the core, which uses the ROM in it that matches the Region setting. No size or hash is required, because MAME sets differ between versions and dumps. The core checks the ROMs it takes from the set by their own checksums.

Create the project

On the last page the Next button reads Create. Chimera then reads every file you added, which can take a while for large files, and checks them against the core's rules. If a file is refused, the wizard goes back to Page 2 and says why. If all is well, the wizard closes and the project opens in TAStudio at the first frame, which is the first picture the game draws.

Some cores add a page that compiles the game's code before the project is made. Flycast does not, so you will not see it.

A project's settings cannot be edited once it exists, because a changed setting is a different machine. To change one, choose New Chimera Project again. The wizard opens filled in with your last answers, so you change that one setting and go through the pages to Create again.
